1. Граф взаимодействий: что нового он даёт с нуля
Связи через несколько шагов, которых не видит матричная факторизация
📖 Базовые термины
Граф (graph)
Набор вершин (узлов) и рёбер между ними. В рекомендациях вершины — пользователи и объекты, рёбра — факты взаимодействия.
Двудольный граф (bipartite graph)
Граф, вершины которого делятся на две группы, а рёбра идут только между группами, никогда внутри. Граф «пользователи — объекты» именно такой: пользователь не связан напрямую с другим пользователем.
Степень вершины (degree, $d_v$)
Число рёбер, выходящих из вершины. Для пользователя — сколько объектов он взял, для объекта — сколько людей его взяли. Ключевая величина: именно на неё нормируют, чтобы популярные вершины не доминировали.
Соседи (neighbors, $\mathcal{N}(v)$)
Вершины, соединённые с данной ребром. Соседи пользователя — его объекты, соседи объекта — его пользователи.
Хоп (hop)
Один шаг по ребру. «Второй хоп от пользователя» — это другие пользователи, взявшие те же объекты. «Третий хоп» — объекты, которые взяли эти пользователи.
Матрица смежности (adjacency matrix, $A$)
Квадратная матрица размера «все вершины × все вершины», где $A_{uv}=1$, если есть ребро. Для двудольного графа она имеет блочный вид: два нулевых блока по диагонали и матрица взаимодействий $R$ вне диагонали.
Распространение (propagation / message passing)
Основная операция графовых сетей: вершина собирает векторы своих соседей и обновляет собственный. Повторение $K$ раз означает, что информация доходит на $K$ хопов.
GNN (Graph Neural Network)
Общее название нейросетей, работающих на графах через распространение. LightGCN — их предельно упрощённая версия, специализированная под рекомендации.
🤏 На пальцах: что видит граф, чего не видит факторизация

Матричная факторизация из темы 6.1 работает с прямыми взаимодействиями: у пользователя есть объекты, у объекта — пользователи. Связи длиннее одного шага она улавливает лишь косвенно, через геометрию пространства.

Граф делает эти связи явными. Путь «Аня взяла товар X → Борис тоже взял X → Борис взял Y» — это цепочка из трёх рёбер, и графовая модель проходит по ней буквально, за три слоя распространения.

Где это важнее всего: у пользователя мало взаимодействий. Прямых сигналов почти нет, но через соседей их набирается достаточно. Формально это и есть та же проблема разрежённости, что в теме 6.1, — граф атакует её с другой стороны.

3Что скажет матричная факторизация

MF смотрит только на прямые взаимодействия. Профиль u₁ = {i₁, i₂}. Ни i₃, ни i₄ в нём нет.

Совстречаемость (тема 6.1, секция 3): C(i₁, i₃) = кто взял оба? — никто → 0 C(i₂, i₃) = 0 C(i₁, i₄) = 0 C(i₂, i₄) = 0 score item-item для u₁: score(i₃) = 0 + 0 = 0 score(i₄) = 0 + 0 = 0 Оба кандидата неразличимы. Модель не может выбрать.

Это не недостаток реализации, а свойство подхода: item-item видит только пути длины 2 (объект → пользователь → объект). Путь длины 3 ему недоступен.

2. Симметричная нормировка: единственная формула с нуля
Почему делят именно на корни степеней
📖 Термины этой секции
Матрица степеней (degree matrix, $D$)
Диагональная матрица, где на позиции $(v,v)$ стоит степень вершины $v$. Вне диагонали нули. Нужна исключительно для нормировки.
Симметричная нормировка (symmetric normalization)
Преобразование $\tilde A = D^{-1/2} A D^{-1/2}$. Вес ребра $(u,i)$ становится $1/\sqrt{d_u d_i}$ — делится на корни степеней обоих концов.
Нормировка по строкам (row normalization)
Альтернатива: $D^{-1}A$, вес ребра $1/d_u$. Строки суммируются в единицу, получается матрица переходов случайного блуждания. Несимметрична: вес $u \to i$ не равен весу $i \to u$.
Собственное значение (eigenvalue)
Число $\lambda$, для которого $\tilde A x = \lambda x$ при некотором ненулевом $x$. Практический смысл здесь: наибольшее по модулю собственное значение определяет, растут или затухают векторы при многократном применении $\tilde A$. У симметрично нормированной матрицы все $|\lambda| \le 1$, что и обеспечивает устойчивость.
Взрыв и затухание величин (explosion / vanishing)
Что происходит без нормировки: при $\lambda > 1$ векторы растут экспоненциально с числом слоёв, при $\lambda < 1$ — схлопываются в ноль. Нормировка удерживает $\lambda = 1$, и векторы остаются в разумном масштабе.
🤏 На пальцах: почему делим, и почему на корни

Почему вообще делим. Без нормировки вершина складывает векторы всех соседей. У популярного объекта соседей тысячи, у нишевого — три. Сумма тысячи векторов на порядки больше суммы трёх, и после нескольких слоёв популярные вершины полностью подавляют остальные.

Почему на корни, а не на саму степень. Деление на $d_u$ (нормировка по строкам) учитывает только принимающую сторону. Но передающая сторона тоже важна: сигнал от вершины с тысячей соседей «размазан» по ним, и каждому достаётся мало. Корни из обеих степеней учитывают обе стороны сразу и делают матрицу симметричной — вес $u \to i$ равен весу $i \to u$.

Что даёт симметрия технически. У симметричной матрицы все собственные значения вещественны, а после такой нормировки они лежат в $[-1, 1]$. Это гарантирует, что векторы не взорвутся и не схлопнутся при любом числе слоёв.

📐 Симметричная нормировка
$$\tilde A = D^{-1/2}\, A\, D^{-1/2}, \qquad \tilde A_{ui} = \frac{A_{ui}}{\sqrt{d_u}\,\sqrt{d_i}}$$

Для двудольного графа $A$ имеет блочный вид $\begin{pmatrix}0 & R\\ R^\top & 0\end{pmatrix}$: пользователи связаны только с объектами и наоборот. Нулевые блоки на диагонали — прямое следствие двудольности.

3. LightGCN: три слоя с полными вычислениями с нуля
Два объекта с идентичными стартовыми векторами расходятся только за счёт структуры графа
📖 Термины этой секции
Слой распространения (propagation layer)
Один шаг «собери векторы соседей, взвесь, сложи». Результат $K$-го слоя содержит информацию из вершин, удалённых ровно на $K$ хопов.
LightGCN
Графовая модель для рекомендаций, в которой из обычного GCN убрано всё, кроме взвешенного суммирования соседей: нет матриц весов, нет нелинейностей, нет самопетель. Обучаемые параметры — только стартовые векторы вершин.
Слоевая комбинация (layer combination)
Итоговый вектор вершины — среднее (или взвешенная сумма) её векторов со всех слоёв, включая нулевой. Заменяет самопетли и одновременно смягчает over-smoothing.
Нулевой слой ($e^{(0)}$)
Исходный обучаемый эмбеддинг вершины, до всякого распространения. Единственное, что оптимизируется градиентным спуском.
Пути в графе (paths)
Формально $K$ слоёв распространения эквивалентны суммированию по всем путям длины $\le K$ с весами, равными произведению весов рёбер вдоль пути. Отсюда прямая связь: объект, до которого нет пути длины $\le K$, не получит от пользователя ничего.
📐 LightGCN: правило распространения и итоговый вектор
$$\mathbf{e}_u^{(k+1)} = \sum_{i \in \mathcal{N}(u)} \frac{1}{\sqrt{d_u}\sqrt{d_i}}\,\mathbf{e}_i^{(k)}, \qquad \mathbf{e}_i^{(k+1)} = \sum_{u \in \mathcal{N}(i)} \frac{1}{\sqrt{d_u}\sqrt{d_i}}\,\mathbf{e}_u^{(k)}$$ $$\mathbf{e}_v = \frac{1}{K+1}\sum_{k=0}^{K}\mathbf{e}_v^{(k)}, \qquad \hat y_{ui} = \mathbf{e}_u^{\top}\mathbf{e}_i$$

Ни одной обучаемой матрицы в распространении. Всё, что оптимизируется, — векторы $\mathbf{e}^{(0)}$. Само распространение — фиксированное линейное преобразование, определяемое только структурой графа.

✓Что важно понять из трассировки

① Распространение — это фиксированное линейное преобразование. Обучаются только векторы слоя 0; сама операция параметров не имеет и во время обучения не меняется.

② $K$ слоёв = все пути длины $\le K$. Объект, до которого нет пути длины $\le K$, получит ровно ноль вклада от пользователя. Отсюда прямое правило выбора $K$: он должен покрывать типичное расстояние до релевантных кандидатов.

③ Усреднение слоёв — не косметика. Без нулевого слоя в среднем модель потеряет исходные векторы, а без промежуточных — начнёт страдать от over-smoothing (секция 5).

# LightGCN: всё распространение — четыре строки
import torch, torch.nn as nn, torch.nn.functional as F

class LightGCN(nn.Module):
    def __init__(self, n_users, n_items, dim=64, n_layers=3):
        super().__init__()
        self.emb = nn.Embedding(n_users + n_items, dim)   # ЕДИНСТВЕННЫЕ параметры
        nn.init.normal_(self.emb.weight, std=0.1)
        self.n_layers, self.n_users = n_layers, n_users

    def propagate(self, norm_adj):        # norm_adj — разрежённая D^-1/2 A D^-1/2
        e = self.emb.weight
        out = [e]
        for _ in range(self.n_layers):
            e = torch.sparse.mm(norm_adj, e)   # ВЕСЬ слой: одно умножение
            out.append(e)
        return torch.stack(out, dim=1).mean(dim=1)    # слоевая комбинация

    def score(self, norm_adj, users, items):
        all_e = self.propagate(norm_adj)
        eu = all_e[users]
        ei = all_e[self.n_users + items]
        return (eu * ei).sum(-1)

# Построение нормированной матрицы смежности
import scipy.sparse as sp, numpy as np

def build_norm_adj(R, n_users, n_items):
    """R: (n_users, n_items) разрежённая бинарная матрица."""
    n = n_users + n_items
    A = sp.lil_matrix((n, n))
    A[:n_users, n_users:] = R          # блочная структура двудольного графа
    A[n_users:, :n_users] = R.T
    A = A.tocsr()

    deg = np.asarray(A.sum(axis=1)).ravel()
    d_inv_sqrt = np.power(deg, -0.5, where=deg > 0)
    d_inv_sqrt[np.isinf(d_inv_sqrt)] = 0.0
    D = sp.diags(d_inv_sqrt)
    norm = (D @ A @ D).tocoo()          # симметричная нормировка

    idx = torch.LongTensor(np.vstack([norm.row, norm.col]))
    val = torch.FloatTensor(norm.data)
    return torch.sparse_coo_tensor(idx, val, (n, n)).coalesce()

Про стоимость инференса. Распространение — это $K$ умножений разрежённой матрицы на плотную. Для графа с 47 млн рёбер и $\dim=64$ один слой стоит около $47\text{млн} \times 64 \approx 3\times10^9$ операций, три слоя — $9\times10^9$, то есть секунды на GPU. Но делать это на каждый запрос не нужно: результат распространения пересчитывается раз в сутки и кладётся в тот же ANN-индекс, что и векторы two-tower из темы 6.2. С точки зрения инференса LightGCN неотличим от матричной факторизации.

📖 Термины этой секции
Классический GCN (Graph Convolutional Network)
Общая графовая сеть: на каждом слое соседи не просто суммируются, но и пропускаются через обучаемую матрицу весов $W$ и нелинейность: $e^{(k+1)} = \sigma(\tilde A e^{(k)} W^{(k)})$.
Матрица преобразования (feature transformation, $W$)
Обучаемая матрица, «перемешивающая» компоненты вектора на каждом слое. Нужна, когда вход — осмысленные признаки (текст, изображение), которые надо преобразовать в полезное представление.
Нелинейность (nonlinearity, ReLU)
Функция активации, обнуляющая отрицательные значения. Даёт сети способность выражать сложные функции — но только если на входе есть что усложнять.
Ablation-исследование
Метод оценки вклада компонента: убрать его и посмотреть на метрику. Именно так было установлено, что $W$ и ReLU в рекомендательном GCN вредят.
Обучаемые ID-эмбеддинги как вход
Ключ к пониманию всей секции: на вход графовой модели в рекомендациях подаются не признаки, а свободные обучаемые векторы. Их и так можно поставить куда угодно в пространстве — дополнительное преобразование ничего не добавляет.
🤏 На пальцах: почему нелинейности здесь лишние

В обычном GCN на вход подаются признаки: текст статьи, свойства молекулы, атрибуты узла. Их надо преобразовать во что-то полезное — отсюда матрица $W$ и нелинейность.

В рекомендациях на вход подаются свободные обучаемые векторы. Они не несут никакого исходного смысла — оптимизация ставит их куда угодно. Умножать свободный вектор на обучаемую матрицу бессмысленно: композиция двух обучаемых объектов выражает ровно то же, что один.

А вредят они потому, что добавляют параметров без выразительности. Больше параметров при том же объёме данных — больше переобучение и труднее оптимизация. ReLU вдобавок обнуляет половину компонент на каждом слое, теряя информацию.

2Но и одна матрица не нужна
E³ = Ã³ E⁰ W E⁰ — свободно обучаемая матрица векторов. Обозначим E⁰' = E⁰ W — это тоже свободно обучаемая матрица. E³ = Ã³ E⁰' Множество достижимых E³ при обучении E⁰ и W — ровно то же, что при обучении одного E⁰'.

Выразительность идентична, параметров больше. Модель с $W$ не может выразить ничего, что не может выразить модель без неё, но имеет лишние 4096 параметров на каждый слой, которые надо обучить и которые могут переобучиться.

3Что добавляет ReLU и почему это плохо

С нелинейностью схлопывание невозможно — она действительно добавляет выразительности. Но посмотрим, чем это оборачивается:

Доля обнулённых компонент При случайной инициализации примерно половина компонент отрицательна. Слой 1: ReLU обнуляет ≈ 50% компонент Слой 2: из оставшихся снова ≈ 50% → живых 25% Слой 3: живых ≈ 12.5% При dim = 64 после трёх слоёв в среднем работает 8 компонент из 64.

Информация теряется безвозвратно. В обычном GCN это компенсируется тем, что $W$ может «повернуть» вектор так, чтобы нужная информация попала в положительные компоненты. В LightGCN такой матрицы нет — и не нужно, потому что нет и ReLU.

Плюс отдельная проблема: ReLU разрушает интерпретацию через пути. Без неё $K$ слоёв в точности равны сумме по путям длины $\le K$ с явными весами. С ReLU эта связь исчезает, и понять, почему объект получил высокий скор, становится нельзя.

5. Over-smoothing: почему нельзя много слоёв средний
Механизм схождения всех векторов к одному направлению
📖 Термины этой секции
Over-smoothing (пересглаживание)
Эффект, при котором с ростом числа слоёв векторы всех вершин становятся всё более похожими друг на друга, и модель теряет способность их различать. Фундаментальное ограничение глубины любых графовых сетей.
Усреднение как сглаживание
Механизм в одну фразу: каждый слой заменяет вектор вершины на взвешенное среднее соседей. Повторное усреднение по любому связному графу неизбежно стягивает всё к общему значению — как многократное размытие изображения.
Доминирующее собственное направление
Математическая причина: при многократном умножении на $\tilde A$ выживает только компонента вдоль собственного вектора с наибольшим по модулю собственным значением. Все остальные компоненты затухают как $(\lambda_i/\lambda_1)^K$.
Спектральный зазор (spectral gap)
Разница между наибольшим и вторым собственными значениями. Чем он больше, тем быстрее наступает over-smoothing. Плотные, хорошо связные графы страдают сильнее разреженных.
Остаточные связи (residual connections)
Приём борьбы: к результату слоя прибавляется его вход, $e^{(k+1)} = \tilde A e^{(k)} + e^{(k)}$. Исходная информация сохраняется, и схождение замедляется. Слоевая комбинация LightGCN выполняет ту же роль.
🤏 На пальцах: размытие изображения

Каждый слой — это усреднение по соседям. То же самое делает фильтр размытия в графическом редакторе.

Одно размытие убирает шум и оставляет структуру — полезно. Двадцать размытий подряд превращают любое изображение в однородное серое пятно, где ничего не различить.

С графом ровно так же. Два-три слоя обогащают вектор информацией о соседстве. Восемь слоёв стирают индивидуальность: все вершины становятся почти одинаковыми, и скор перестаёт зависеть от того, кому что рекомендуем.

2Почему это происходит — механизм

Разложим начальный вектор по собственным векторам матрицы $\tilde A$:

e⁰ = c₁·v₁ + c₂·v₂ + c₃·v₃ + … где v₁, v₂, … — собственные векторы Ã, λ₁, λ₂, … — соответствующие собственные значения, |λ₁| ≥ |λ₂| ≥ … После K слоёв: e^K = Ã^K e⁰ = c₁·λ₁^K·v₁ + c₂·λ₂^K·v₂ + c₃·λ₃^K·v₃ + … Вынесем λ₁^K: e^K = λ₁^K · [ c₁·v₁ + c₂·(λ₂/λ₁)^K·v₂ + c₃·(λ₃/λ₁)^K·v₃ + … ] ↑ затухает ↑ затухает быстрее
Численно: типичные значения для рекомендательного графа λ₁ = 1.000, λ₂ = 0.870, λ₃ = 0.760 Отношение (λ₂/λ₁)^K: K = 1: 0.870 K = 2: 0.757 K = 3: 0.659 K = 5: 0.498 K = 8: 0.328 K = 12: 0.187 K = 20: 0.062

Все компоненты кроме первой затухают экспоненциально. В пределе $e^K \to \lambda_1^K c_1 v_1$ — то есть направление вектора становится одинаковым у всех вершин, различаются только длины. А для косинусной близости длины не важны, поэтому все пары становятся «похожими».

3Что стоит за первым собственным вектором

Для симметрично нормированной матрицы связного графа $v_1$ известен явно:

v₁(вершина v) ∝ √d(v) То есть предельное направление — это просто корень из степени. Практический смысл: при большом K скор превращается в score(u, i) ≈ const · √d(u) · √d(i) → ранжирование сводится к сортировке по популярности

Отсюда наглядное объяснение провала: глубокая графовая модель вырождается в рекомендацию популярного. При $K=12$ Recall@20 составил 0.0604 — это примерно уровень базовой линии «показывай популярное» из темы 6.1.

4Как слоевая комбинация смягчает эффект
Без слоевой комбинации — берём только последний слой e = e^K → вся масса на затухших компонентах, эффект максимален Со слоевой комбинацией — среднее по всем слоям e = (e⁰ + e¹ + … + e^K)/(K+1) Компонента вдоль v₂ получает вес: (1 + 0.870 + 0.757 + 0.659)/4 = 3.286/4 = 0.822 вместо 0.659 при K=3 без комбинации. Компонента вдоль v₁ получает вес 1.000 в обоих случаях. → отношение «полезный сигнал / доминирующее направление» улучшается в 0.822/0.659 = 1.25 раза

Это и объясняет строку из ablation секции 4: слоевая комбинация дала +3.3% поверх LightGCN без неё. Она частично возвращает то, что съедает over-smoothing.

6. Случайные блуждания и Personalized PageRank средний
Дешёвая альтернатива обучению, часто не уступающая ему
📖 Термины этой секции
Случайное блуждание (random walk)
Процесс: стоим в вершине, выбираем случайного соседа, переходим, повторяем. Простейший способ «исследовать» граф без всякого обучения.
PageRank
Исходно — алгоритм ранжирования веб-страниц: важность страницы определяется вероятностью оказаться на ней при долгом случайном блуждании по ссылкам. Даёт глобальную важность, одинаковую для всех.
Personalized PageRank (PPR)
Модификация: блуждание с некоторой вероятностью $\alpha$ телепортируется обратно в стартовую вершину, а не в случайную. Результат — распределение, персональное для этой вершины: «куда чаще всего попадаешь, гуляя от неё».
Вероятность рестарта (restart / teleport probability, α)
Шанс прервать блуждание и вернуться в старт на каждом шаге. Управляет радиусом: большая $\alpha$ — короткие блуждания, локальный охват; малая — длинные, глобальный.
Ожидаемая длина блуждания
При вероятности рестарта $\alpha$ среднее число шагов до возврата равно $1/\alpha$. При $\alpha = 0.15$ это примерно 6.7 шагов — то есть PPR «видит» граф на глубину около семи хопов, гораздо дальше, чем 3 слоя LightGCN.
Метод Монте-Карло (Monte Carlo estimation)
Оценка PPR не решением уравнения, а прямым запуском множества блужданий и подсчётом посещений. Даёт приближение, зато масштабируется на любой граф и тривиально параллелится.
🤏 На пальцах: гуляем от пользователя и считаем, где чаще оказываемся

Стартуем в вершине пользователя. Идём к случайному его объекту, оттуда к случайному пользователю этого объекта, оттуда снова к объекту — и так далее. Иногда (с вероятностью $\alpha$) телепортируемся обратно в старт.

Считаем, в каких объектах побывали чаще всего. Это и есть рекомендации: объекты, до которых от пользователя «легко дойти» по многим коротким путям.

Главное преимущество: обучения нет вообще. Ни эпох, ни learning rate, ни функции потерь. Только граф и генератор случайных чисел. Часто это даёт 85–95% качества обученной модели за долю усилий.

📐 Personalized PageRank
$$\boldsymbol{\pi}_u = \alpha\, \mathbf{e}_u + (1-\alpha)\, P^\top \boldsymbol{\pi}_u$$

$\mathbf{e}_u$ — вектор с единицей в стартовой вершине, $P$ — матрица переходов ($P_{vw} = 1/d_v$ для соседей).

$$\boldsymbol{\pi}_u = \alpha\sum_{k=0}^{\infty}(1-\alpha)^k (P^\top)^k\,\mathbf{e}_u$$

Вторая форма показывает связь с LightGCN: PPR — тоже суммирование по путям, но с геометрически убывающими весами $(1-\alpha)^k$ и по бесконечному числу шагов, а не по $K$. То есть PPR можно рассматривать как LightGCN с бесконечной глубиной и встроенной защитой от over-smoothing: дальние пути автоматически весят меньше.

# PPR методом Монте-Карло: без обучения, тривиально параллелится
import numpy as np
from collections import Counter

def ppr_walks(neighbors, start, alpha=0.15, n_walks=10_000, max_len=100, rng=None):
    """neighbors: dict вершина -> список соседей."""
    rng = rng or np.random.default_rng(0)
    visits = Counter()
    for _ in range(n_walks):
        v = start
        for _ in range(max_len):
            if rng.random() < alpha:          # рестарт
                v = start
                continue
            nb = neighbors[v]
            if not nb:
                break
            v = nb[rng.integers(len(nb))]     # равновероятный сосед
            visits[v] += 1
    total = sum(visits.values()) or 1
    return {k: c / total for k, c in visits.items()}

7. Node2vec: обучение векторов на блужданиях средний
Мост между случайными блужданиями и обучаемыми представлениями
📖 Термины этой секции
Node2vec
Метод получения векторов вершин: запускаем случайные блуждания, полученные последовательности вершин трактуем как «предложения», и обучаем на них word2vec. Вершины, часто встречающиеся рядом в блужданиях, получают близкие векторы.
Skip-gram
Схема обучения word2vec: по центральному элементу предсказываем соседей в окне. В графовом контексте — по вершине предсказываем те, что встречаются рядом в блужданиях.
Окно контекста (context window)
Сколько соседних позиций в последовательности считать «контекстом». Окно 5 означает, что вершина связывается с теми, что встретились в пределах пяти шагов блуждания.
Параметр p — возврат (return parameter)
Управляет вероятностью вернуться в вершину, откуда только что пришли. Большое $p$ отталкивает от возвратов, блуждание уходит дальше.
Параметр q — обход (in-out parameter)
Управляет выбором между «остаться рядом со стартом» и «уйти вглубь». $q > 1$ даёт локальный обход (аналог поиска в ширину), $q < 1$ — уход вдаль (аналог поиска в глубину).
Гомофилия и структурная эквивалентность
Два разных вида похожести. Гомофилия — вершины из одного «сообщества» (уход вглубь, $q < 1$). Структурная эквивалентность — вершины с похожей ролью в графе, даже если далеко друг от друга (локальный обход, $q > 1$). Для рекомендаций почти всегда нужна первая.
🤏 На пальцах: граф как текст

Случайное блуждание порождает последовательность вершин: u₁ i₁ u₂ i₃ u₃ i₄ …

Это очень похоже на предложение. Вершины идут по порядку, соседние по позиции связаны по смыслу. Значит, к ним применим word2vec — метод, изначально придуманный для слов.

Отличие от чистого PPR: там мы просто считали посещения, здесь мы обучаем векторы. Векторы можно использовать дальше — подавать в другую модель, искать через ANN-индекс, комбинировать с признаками. Частоты посещений так использовать нельзя.

📐 Смещённое блуждание node2vec
$$\pi_{vx} = \begin{cases}\dfrac{1}{p}, & d_{tx} = 0 \;\text{(вернулись назад)}\\[8pt] 1, & d_{tx} = 1 \;\text{(сосед и текущей, и предыдущей)}\\[8pt] \dfrac{1}{q}, & d_{tx} = 2 \;\text{(уходим дальше)}\end{cases}$$

$t$ — предыдущая вершина, $v$ — текущая, $x$ — кандидат на переход, $d_{tx}$ — расстояние от $x$ до $t$. Веса ненормированы; на практике их делят на сумму. При $p=q=1$ получается обычное равномерное блуждание.

2Три набора параметров
Вариант A: p = 1, q = 1 — обычное равномерное блуждание вес(u₁) = 1/p = 1/1 = 1.0 вес(u₂) = 1/q = 1/1 = 1.0 сумма = 2.0 P(u₁) = 1.0/2.0 = 50% P(u₂) = 50% Вариант B: p = 4, q = 0.25 — уход вглубь (гомофилия) вес(u₁) = 1/4 = 0.25 вес(u₂) = 1/0.25 = 4.00 сумма = 4.25 P(u₁) = 0.25/4.25 = 5.9% P(u₂) = 4.00/4.25 = 94.1% ← почти всегда уходим дальше Вариант C: p = 0.25, q = 4 — локальный обход (структура) вес(u₁) = 1/0.25 = 4.00 вес(u₂) = 1/4 = 0.25 сумма = 4.25 P(u₁) = 94.1% P(u₂) = 5.9% ← почти всегда возвращаемся, топчемся на месте

8. Гетерогенные графы: несколько типов вершин и рёбер продвинутый
Когда в графе есть не только «взял», но и «просмотрел», «купил», «вернул»
📖 Термины этой секции
Гетерогенный граф (heterogeneous graph)
Граф, где вершины бывают разных типов (пользователь, товар, бренд, категория, продавец) и рёбра тоже (просмотрел, купил, вернул, принадлежит бренду). В отличие от простого двудольного, где всё однотипно.
Метапуть (metapath)
Шаблон пути по типам вершин, например «пользователь → купил → товар → принадлежит → бренд → принадлежит → товар». Задаёт осмысленный способ связать вершины, вместо блуждания вслепую.
Граф знаний (knowledge graph)
Гетерогенный граф, где рёбра — это факты вида «субъект — отношение — объект». В рекомендациях используется как источник дополнительной структуры: «фильм снят режиссёром X», «товар относится к бренду Y».
Отношение-специфичное преобразование (relation-specific transform)
Своя матрица весов или свой вес нормировки для каждого типа ребра. Позволяет модели по-разному учитывать покупку и просмотр.
Внимание по типам рёбер (edge-type attention)
Обучаемые веса важности типов, вместо заданных вручную. Модель сама выясняет, что покупка информативнее просмотра — и во сколько раз.

9. Масштаб: граф не помещается в память продвинутый
Сэмплирование соседей и почему оно работает
📖 Термины этой секции
Полнобатчевое обучение (full-batch training)
Распространение по всему графу сразу, на каждом шаге. Просто и точно, но требует держать в памяти векторы всех вершин и всю матрицу смежности.
Взрыв соседства (neighborhood explosion)
Главная проблема масштабирования: чтобы точно вычислить вектор одной вершины на слое $K$, нужны все её соседи на слое $K-1$, их соседи на $K-2$ и так далее. При средней степени 100 и $K=3$ это $100^3 = 10^6$ вершин ради одной.
Сэмплирование соседей (neighbor sampling)
Решение: на каждом слое брать не всех соседей, а случайные $S$ штук. Превращает экспоненциальный рост в контролируемый: $S_1 \times S_2 \times S_3$ вместо $d^3$.
Кластерное разбиение (graph clustering / METIS)
Альтернатива: разбить граф на плотно связанные куски и обучаться на них как на самостоятельных графах. Рёбер между кусками мало, поэтому потери информации умеренные.
Несмещённость оценки
Почему сэмплирование не ломает обучение: случайная выборка соседей даёт несмещённую оценку полной суммы, если правильно перевзвесить. Дисперсия растёт, но градиент в среднем верный — та же логика, что у стохастического градиентного спуска.

3Почему сэмплирование не ломает обучение
Точная сумма по всем соседям e(v) = Σ_{i ∈ N(v)} w_i · e(i) где |N(v)| = d Оценка по выборке из S соседей ê(v) = (d/S) · Σ_{i ∈ выборка} w_i · e(i) ↑ перевзвешивание Математическое ожидание: E[ê(v)] = (d/S) · S · (1/d) · Σ_{все i} w_i·e(i) = e(v) ← НЕСМЕЩЁННАЯ оценка

Оценка верна в среднем. Дисперсия, конечно, есть — но это ровно та же ситуация, что при стохастическом градиентном спуске: шумный градиент по мини-батчу вместо точного по всем данным. Обучение работает, просто требует чуть больше шагов.

10. Инференс и обновление графа продвинутый
Эксплуатационная сторона, о которой обычно не пишут
📖 Термины этой секции
Трансдуктивная модель (transductive)
Модель, дающая векторы только для вершин, присутствовавших при обучении. Новая вершина требует переобучения. LightGCN и node2vec трансдуктивны по умолчанию.
Индуктивная модель (inductive)
Модель, умеющая вычислить вектор новой вершины без переобучения — по её признакам и соседям. Требует, чтобы на вход подавались признаки, а не свободные ID-эмбеддинги.
Предрасчёт векторов (embedding precomputation)
Ключевой практический факт: распространение делается офлайн раз в сутки, результат кладётся в ANN-индекс. На инференсе графовая модель неотличима от матричной факторизации по стоимости.
Инкрементальное обновление
Пересчёт только для затронутой части графа при появлении новых рёбер, вместо полного прогона. Возможен потому, что распространение локально: новое ребро влияет лишь на вершины в $K$ хопах от него.

3Главное ограничение: новая вершина
Новый объект i_new появился в каталоге. Его вектор слоя 0 — случайная инициализация, ничему не обучен. Распространение соберёт соседей... но соседей у него НЕТ. e¹(i_new) = сумма по пустому множеству = 0 e²(i_new) = 0 e³(i_new) = 0 итоговый вектор = (e⁰ + 0 + 0 + 0)/4 = e⁰/4 = случайный шум / 4

Та же проблема, что у матричной факторизации в теме 6.3, и по той же причине: без взаимодействий структуры нет, а свободный вектор ничему не обучен.

Три способа сделать модель индуктивной ① Вместо свободного e⁰ подавать проекцию признаков: e⁰(i) = MLP(категория, бренд, текст) → новый объект получает осмысленный вектор сразу → но возвращаются матрицы весов, которые убирали в секции 4 (и это правильно: теперь на входе признаки, а не свободные векторы) ② Виртуальные рёбра: связать новый объект с вершинами-атрибутами (бренд, категория) — тогда распространение через них даст ненулевой вектор ③ Гибрид: контентный вектор до накопления рёбер, плавный переход к графовому по мере роста степени — тот же прогрев w(n) = n/(n+n₀) из темы 6.3

Граф плотный. Спектральный зазор велик, over-smoothing наступает при $K=2$, и модель вырождается почти сразу. Симптом: средний косинус случайных пар выше 0.5 уже на двух слоях.

13. Подводные камни средний
Пятнадцать ошибок, специфичных для графовых моделей
1
Тестовые рёбра остались в графе. Завышение почти втрое (0.318 против 0.109). Специфичная для графов ошибка: структура графа и обучающая выборка задаются отдельно, и рассинхронизировать их очень легко.
2
Нет нормировки матрицы смежности. Не тонкая настройка, а условие работоспособности: без неё норма растёт на 2–3 порядка за слой и float32 переполняется на четвёртом.
3
Нормировка по строкам вместо симметричной. Матрица становится несимметричной, вес $u\to i$ не равен $i\to u$, теряется учёт степени передающей стороны.
4
Добавлены самопетли по привычке из GCN. В LightGCN их роль выполняет слоевая комбинация с нулевым слоем. Двойной учёт исходного вектора ухудшает результат.
5
Оставлены матрицы весов и ReLU. Ablation: убрать ReLU +7.6%, убрать W +9.0%, убрать оба +15.6%. При свободных ID-эмбеддингах на входе они не добавляют выразительности, только параметры.
6
Слишком много слоёв. Over-smoothing: при K=12 средний косинус случайных пар 0.958, а Recall падает до уровня «показывай популярное». Оптимум обычно 2–4.
7
Число слоёв перенесено из статьи. Оптимальное K зависит от плотности вашего графа, а не от размера каталога. На плотном графе оптимум 2, на разрежённом 3–4.
8
Нет слоевой комбинации. Берётся только последний слой — теряется исходный вектор и усиливается over-smoothing. Даёт −3.3% в ablation.
9
Все типы рёбер свалены в один граф. Просмотры составляют 87% рёбер и топят покупки. Результат хуже, чем граф из одних покупок. Нужны веса по типу — соотношение около 1:3:10.
10
Метапути оцениваются только по среднему Recall. Путь через продавца даёт −0.8% на среднем, но его удаление роняет покрытие каталога с 21.4% до 16.4%.
11
Попытка обучать полнобатчево на большом графе. При степени 112 и K=3 подграф одной вершины — 1.4 млн вершин. Сэмплирование [15,10,5] даёт 99.3% качества при подграфе в 1500 раз меньше.
12
Нет перевзвешивания при сэмплировании. Оценка суммы по выборке несмещена только при умножении на $d/S$. Без него векторы систематически занижены у вершин высокой степени.
13
Новый объект получает шум. LightGCN трансдуктивен: у вершины без рёбер все слои распространения дают ноль, остаётся только необученный $e^{(0)}$. Recall 0.008 против 0.112 с контентной проекцией.
14
Полное переобучение при каждом изменении графа. Пересчёт одного распространения по свежему графу со старыми $e^{(0)}$ стоит 4 минуты и даёт 97.4% качества — позволяет обновляться ежечасно.
15
Внедрение LightGCN без проверки PPR. PPR даёт 92% качества за 40 минут без обучения. Если он не бьёт item-item, граф задаче не помогает, и обучаемая модель это не исправит.
14. System Design продвинутый
Пять кейсов с нюансами валидации
📌
Pinterest — графовая модель на миллиардах пинов
Как обучать GNN, который не помещается в память

Задача. Граф из миллиардов пинов и досок. Пин принадлежит доскам, доски содержат пины — естественный двудольный граф с очень высокой степенью у популярных досок.

Решение. Обучение на сэмплированных подграфах вместо полного графа, причём соседи выбираются не равномерно, а по важности: вероятность попасть в выборку пропорциональна вкладу вершины в PPR от целевой. Это резко снижает дисперсию оценки по сравнению с равномерным сэмплированием — при том же размере выборки.

Почему так. У доски с миллионом пинов равномерная выборка из 10 соседей почти наверняка даст случайный шум. Выборка по важности гарантирует, что попадут пины, действительно связанные с целевым.

Нюанс валидации. Метрика считается отдельно по степени вершины — как в таблице секции 11. Агрегат определяется популярными пинами, у которых граф даёт мало, и скрывает основной эффект на хвосте. Плюс отдельно контролируется, что подграфы покрывают достаточную долю рёбер: если сэмплирование теряет больше 10% связей, оценка перестаёт быть репрезентативной.

Подводный камень. Сэмплирование по важности вносит смещение, которое надо компенсировать перевзвешиванием. Без компенсации модель систематически переоценивает популярные вершины — тот же механизм смещения популярности, что в теме 6.1, только через другой канал.

🛒
Alibaba — гетерогенный граф электронной коммерции
Пользователи, товары, продавцы, бренды в одном графе

Задача. В каталоге сотни миллионов товаров, и большинство имеет мало взаимодействий. Прямого коллаборативного сигнала не хватает, но есть богатая структура: товар принадлежит бренду, бренд — категории, товар продаётся продавцом.

Решение. Граф включает вершины всех типов и рёбра нескольких видов, каждый со своим весом. Хвостовой товар получает сигнал через бренд и категорию: даже при трёх собственных взаимодействиях он связан с сотнями товаров того же бренда, а через них — с их пользователями.

Почему так. Это прямой ответ на разрежённость: структура каталога компенсирует нехватку поведенческих данных. Товар без истории оказывается не изолированной вершиной, а частью плотного кластера бренда.

Нюанс валидации. Ablation ведётся по типам рёбер, и оценивается и качество, и покрытие каталога. Тип ребра, дающий менее процента к среднему Recall, может держать несколько процентов покрытия — то есть вытаскивать хвост, который иначе не показывается вообще. Решение об удалении компонента по одному среднему Recall — типичная ошибка.

Подводный камень. Вершины-атрибуты (популярный бренд) имеют огромную степень и становятся «магистралями»: почти любой путь в графе проходит через них, и все товары бренда получают почти одинаковые векторы. Лечится ограничением степени таких вершин или отдельным, пониженным весом для рёбер к атрибутам.

🎵
Spotify — плейлисты как рёбра графа
Приём, дающий на порядки больше связей

Задача. Прямой граф «пользователь — трек» огромен и при этом разрежён: у большинства треков мало прослушиваний от конкретных людей.

Решение. В граф добавляются плейлисты как отдельный тип вершин. Плейлист связан с треками, которые в нём есть, и с пользователями, которые его слушают. Два трека, попавшие в один плейлист, оказываются в двух хопах друг от друга — сильный сигнал совместимости, которого нет в прямых прослушиваниях.

Почему так. Плейлист — это кураторское утверждение «эти треки идут вместе», гораздо более информативное, чем факт прослушивания. Один плейлист из 50 треков даёт 1225 пар связей, тогда как пользователь, послушавший те же 50 треков, — примерно столько же, но с гораздо большим шумом.

Нюанс валидации. Метрика — не CTR, а доля сессий, где пользователь дослушал незнакомый трек до конца и сохранил его. Обычный CTR вознаграждал бы узнаваемые треки, а узнавание — не открытие. Отдельно отслеживается число уникальных артистов в недельной выдаче как прямой контроль схлопывания каталога.

Подводный камень. Плейлисты вносят собственное смещение: редакционные подборки влияют на граф непропорционально своей доле в реальном прослушивании, и алгоритм начинает воспроизводить редакционные предпочтения. Приходится взвешивать рёбра по типу источника плейлиста.

Airbnb — граф с географической структурой
Когда близость в графе должна согласовываться с близостью на карте

Задача. Рекомендовать жильё. Особенность: релевантность жёстко ограничена географией — объект в другом городе бесполезен, каким бы близким он ни был в графе взаимодействий.

Решение. Граф строится с географическими рёбрами: объекты одного района связаны напрямую. Распространение тем самым идёт преимущественно внутри локации, и векторы объектов одного города оказываются близки. Плюс поиск ограничивается географическим фильтром до всякого ранжирования.

Почему так. Без географических рёбер модель обучается на глобальном коллаборативном сигнале и предлагает популярные направления вместо релевантных запросу. Явная географическая структура в графе делает локальность свойством представлений, а не только фильтра.

Нюанс валидации. Метрики считаются внутри рынков, а не глобально: усреднение по всем городам доминируется крупными направлениями и скрывает провал на малых рынках, где данных мало и граф разрежен. Плюс A/B на двустороннем рынке требует рандомизации по рынкам, а не по пользователям, — иначе тестовая группа «съедает» предложение, доступное контрольной.

Подводный камень. Географические рёбра создают очень плотные локальные кластеры, и over-smoothing внутри города наступает быстрее, чем на глобальном графе. Оптимальная глубина оказывается меньше — приходится подбирать $K$ отдельно.

💼
LinkedIn — социальный граф поверх графа взаимодействий
Когда у пользователей есть настоящие связи между собой

Задача. Рекомендовать вакансии, контент, контакты. Особенность платформы: помимо взаимодействий «пользователь — объект» есть прямые связи между пользователями — то, чего нет в обычном двудольном графе.

Решение. Граф перестаёт быть двудольным: добавляются рёбра «пользователь — пользователь». Это даёт короткие пути там, где коллаборативный сигнал их не создаёт: два человека из одной компании связаны напрямую, а не через четыре хопа взаимодействий.

Почему так. Социальная связь — сильный и рано доступный сигнал. Новый пользователь, у которого ноль взаимодействий, но есть двадцать контактов, перестаёт быть изолированной вершиной — то есть социальный граф решает холодный старт из темы 6.3 напрямую.

Нюанс валидации. Оценка ведётся отдельно для пользователей с разным числом связей, и отдельно проверяется, не подменяет ли модель релевантность социальной близостью. Опасность: рекомендовать вакансию просто потому, что туда пошёл знакомый, — это может быть и полезно, и вредно, и различить можно только через долгосрочные метрики (принял ли человек оффер и остался ли), а не через клики.

Подводный камень. Отказ от двудольности ломает часть выкладок: матрица смежности больше не имеет блочного вида, а распространение перестаёт строго чередовать типы вершин. Формулы нормировки остаются теми же, но интерпретация «$K$ слоёв = $K$ хопов между пользователями и объектами» перестаёт быть точной — путь может идти и по социальным рёбрам.

15. Вопросы и ответы 30 вопросов
С опорой на трассировки, а не на определения
1. Что граф даёт такого, чего нет у матричной факторизации?
Явные связи длиннее одного шага. В учебном графе секции 1 объект $i_3$ находится в трёх хопах от $u_1$ (путь $u_1 \to i_1 \to u_2 \to i_3$), а $i_4$ — в пяти. Item-item CF видит только пути длины 2 и потому даёт обоим кандидатам скор ровно 0 — он не может их различить. Графовая модель проходит по трёхшаговому пути буквально, за три слоя распространения.
2. Как показать, что различие создаётся именно структурой графа?
Задать двум кандидатам идентичные стартовые векторы. В трассировке секции 3 у $i_3$ и $i_4$ было $e^{(0)} = [0.4, 0.4]$ у обоих, и скоры на слое 0 совпадали ровно: 0.4000 против 0.4000. После трёх слоёв — 0.4476 против 0.3668. Всё различие порождено исключительно тем, что у них разные соседи и разные расстояния до $u_1$.
3. Почему нормируют матрицу смежности?
Без нормировки вершина складывает векторы всех соседей, а у популярного объекта их тысячи. Расчёт секции 2: при 500 000 соседей норма растёт примерно в 707 раз за слой, за три слоя — в 504 000 раз, и float32 переполняется. Это не тонкая настройка, а условие работоспособности: без неё модель не обучится вообще, градиенты взорвутся на второй-третьей эпохе.
4. Почему делят именно на корни степеней, а не на сами степени?
Деление на $d_u$ (нормировка по строкам) учитывает только принимающую сторону. Но сигнал от вершины с тысячей соседей «размазан» по ним — передающая сторона тоже важна. Корни из обеих степеней учитывают обе стороны и делают матрицу симметричной: вес $u\to i$ равен весу $i\to u$. В примере секции 2 ребро $(u_1, i_2)$ при нормировке по строкам получало 0.5 в одну сторону и 1.0 в другую, при симметричной — 0.707 в обе.
5. Что означает «K слоёв = пути длины ≤ K»?
Формально $K$ слоёв распространения эквивалентны суммированию по всем путям длины не больше $K$ с весами, равными произведению весов рёбер вдоль пути. Практическое следствие прямое: объект, до которого нет пути длины $\le K$, получит от пользователя ровно ноль вклада. В трассировке секции 3 сигнал от $u_1$ дошёл до $i_3$ именно на третьем слое — по пути ровно из трёх рёбер.
6. Как разрыв между кандидатами рос с числом слоёв?
Из таблицы секции 3: только слой 0 — отношение 1.000 (неразличимы), слои 0–1 — 1.050, 0–2 — 1.142, 0–3 — 1.220. Каждый слой добавляет пути на единицу длиннее, и объект с более коротким путём накапливает больше вклада. Это и есть механизм графовой модели в чистом виде.
7. Зачем нужна слоевая комбинация?
Три причины. ① Заменяет самопетли: усреднение включает нулевой слой, поэтому исходный вектор сохраняется. ② Смягчает over-smoothing: компонента вдоль второго собственного направления получает вес 0.822 вместо 0.659 при $K=3$, то есть полезный сигнал усиливается в 1.25 раза относительно доминирующего. ③ В ablation даёт +3.3% поверх LightGCN без неё.
8. Почему из GCN убрали матрицу весов W?
Потому что она не добавляет выразительности при свободных ID-эмбеддингах на входе. Выкладка секции 4: $E^3 = \tilde A^3 E^0 W$, и поскольку $E^0$ свободно обучаема, обозначив $E^{0\prime} = E^0 W$, получаем $E^3 = \tilde A^3 E^{0\prime}$ — множество достижимых состояний то же самое. При этом лишних параметров 4096 на слой, которые надо обучить и которые могут переобучиться. В ablation убирание $W$ дало +9.0%.
9. Чем мешает ReLU?
Обнуляет примерно половину компонент на каждом слое: после трёх слоёв живыми остаются около 12.5% — при $\dim=64$ это 8 компонент из 64. В обычном GCN потерю компенсирует матрица $W$, которая может «повернуть» вектор так, чтобы нужное попало в положительные компоненты; в LightGCN такой матрицы нет. Плюс ReLU разрушает интерпретацию через пути: связь «$K$ слоёв = сумма по путям» перестаёт быть точной, и объяснить высокий скор становится нельзя. Убирание дало +7.6%.
10. Значит ли это, что нелинейности в графовых сетях вообще не нужны?
Нет, вывод узкий и зависит от того, что подаётся на вход. Свободные ID-эмбеддинги преобразовывать нечего — оптимизация и так ставит их куда угодно. Но если на входе текстовые эмбеддинги, признаки объекта или изображения, они несут исходный смысл, который надо перевести в рекомендательное пространство, — и там $W$ с нелинейностями необходимы. В смешанной архитектуре преобразование применяют только к признаковой ветви.
11. Что такое over-smoothing и почему он неизбежен?
С ростом числа слоёв векторы всех вершин становятся всё более похожими. Механизм: каждый слой — это взвешенное усреднение соседей, а многократное усреднение по связному графу неизбежно стягивает всё к общему значению. Метафора точная: одно размытие изображения убирает шум, двадцать превращают его в серое пятно. Замер секции 5: средний косинус случайных пар растёт 0.012 → 0.294 → 0.673 → 0.958 при $K$ = 0, 3, 6, 12.
12. Объясни over-smoothing через собственные значения.
Разложим $e^{(0)}$ по собственным векторам $\tilde A$. После $K$ слоёв $e^{(K)} = \lambda_1^K[c_1 v_1 + c_2(\lambda_2/\lambda_1)^K v_2 + \dots]$. Все компоненты кроме первой затухают экспоненциально: при $\lambda_2/\lambda_1 = 0.87$ множитель идёт 0.870 → 0.659 → 0.328 → 0.187 при $K$ = 1, 3, 8, 12. В пределе остаётся только направление $v_1$ — одинаковое для всех вершин.
13. Что представляет собой первый собственный вектор?
Для симметрично нормированной матрицы связного графа он пропорционален $\sqrt{d(v)}$ — корню из степени. Значит, при большом $K$ скор вырождается в $\text{const}\cdot\sqrt{d(u)}\sqrt{d(i)}$, то есть ранжирование сводится к сортировке по популярности. Это объясняет замер: при $K=12$ Recall@20 составил 0.0604, что примерно равно базовой линии «показывай популярное».
14. Как выбрать число слоёв?
Не переносить из статьи — оно зависит от плотности вашего графа, а не от размера каталога. На плотном графе спектральный зазор велик, over-smoothing наступает быстро, оптимум $K=2$. На разрежённом полезны 3–4, потому что до релевантных вершин дальше идти. Быстрая диагностика вместо перебора: средний косинус случайных пар объектов — ниже 0.15 значит мало слоёв, 0.2–0.4 здоровый диапазон, выше 0.6 значит over-smoothing.
15. Как за две строки проверить, не выродилась ли модель в популярность?
Посчитать ранговую корреляцию Спирмена между скором модели и произведением $\sqrt{d(u)}\sqrt{d(i)}$ на выборке пар. Значение выше 0.8 означает, что модель фактически ранжирует по популярности, и всё графовое распространение работает вхолостую. Проверка требует только степеней вершин и готовых скоров — переобучать ничего не надо.
16. Что такое Personalized PageRank и чем он отличается от обычного?
Обычный PageRank телепортируется в случайную вершину и даёт глобальную важность, одинаковую для всех. PPR телепортируется обратно в стартовую вершину, и результат получается персональным: «куда чаще всего попадаешь, гуляя от этого пользователя». Вероятность рестарта $\alpha$ управляет радиусом: средняя длина блуждания равна $1/\alpha$, при $\alpha=0.15$ это около 6.7 шага.
17. Как связаны PPR и LightGCN?
Оба суммируют по путям, но с разными весами. LightGCN — по путям длины ровно $\le K$, с равными весами слоёв при усреднении. PPR — по путям любой длины, с геометрически убывающими весами $(1-\alpha)^k$. То есть PPR можно считать LightGCN с бесконечной глубиной и встроенной защитой от over-smoothing: дальние пути автоматически весят меньше, а не размывают всё.
18. Насколько PPR хуже обученной модели?
В замере секции 6: PPR Монте-Карло даёт Recall@20 = 0.1003 против 0.1089 у LightGCN, то есть 92% качества — при полном отсутствии обучения. Плюс два эксплуатационных преимущества: реагирует на новые рёбра инкрементально и не имеет проблемы рассинхрона версий. Практический вывод: PPR — правильная первая графовая базовая линия. Если он не бьёт item-item, граф вашей задаче не помогает, и LightGCN это не исправит.
19. Как выбирать α в PPR?
Тот же компромисс, что с числом слоёв. Большая $\alpha$ (0.5) даёт короткие блуждания и узкий локальный охват — теряются дальние связи, Recall 0.0781. Малая $\alpha$ (0.01) размывает распределение к глобальной популярности — Recall 0.0842, то же вырождение, что при over-smoothing. Оптимум около 0.15, что соответствует примерно 7 хопам охвата.
20. Чем node2vec отличается от PPR?
PPR считает частоты посещений, node2vec обучает векторы: последовательности блужданий трактуются как предложения, и на них обучается word2vec. Векторы можно подавать в другую модель, комбинировать с признаками, искать через тот же ANN-индекс, что и two-tower; частоты так использовать нельзя. По качеству node2vec между PPR и LightGCN (0.1021). Главное ограничение — трансдуктивность: новая вершина требует перезапуска блужданий и дообучения.
21. Что делают параметры p и q в node2vec?
$p$ управляет возвратом назад, $q$ — выбором между «остаться рядом» и «уйти вглубь». В трассировке секции 7: при $p=4, q=0.25$ вероятность уйти дальше 94.1%, при $p=0.25, q=4$ — наоборот, 94.1% вероятность вернуться. Для рекомендаций нужен уход вглубь ($q<1$): локальный обход почти не доходит до дальних объектов (0.019 достижимости у $i_4$ против 0.612), а именно неочевидные дальние связи и ценны — ближние и так найдёт item-item.
22. Почему нельзя просто свалить все типы рёбер в один граф?
Потому что типы имеют разное качество сигнала, а количественно доминирует худший. В замере секции 8: просмотры составляют 86.6% рёбер, и граф «всё вместе без различения» дал Recall 0.0798 — хуже, чем граф из одних покупок (0.0912). С весами по типу (просмотр 1, корзина 3, покупка 10) получилось 0.1067, то есть +17% к лучшему одиночному варианту. Больше данных ≠ лучше, если они разного качества и смешаны.
23. Как оценивать вклад метапутей?
Через ablation, но смотреть надо и на качество, и на покрытие каталога. В замере метапуть через продавца дала всего −0.8% к среднему Recall при удалении, но покрытие упало с 21.4% до 16.4% — она вытаскивает хвостовые товары, которых коллаборативный сигнал не достигает. Решение об удалении компонента по одному среднему Recall — прямой путь к потере нужной функции.
24. Что такое взрыв соседства и как с ним бороться?
Чтобы точно вычислить вектор одной вершины на слое $K$, нужны все её соседи на $K-1$, их соседи на $K-2$ и так далее. При средней степени 112 и $K=3$ это $112^3 = 1.4$ млн вершин ради одной. Решение — сэмплирование: брать не всех соседей, а по $S$ штук с убывающими $S$ по глубине. Схема [10,10,5] даёт подграф из 610 вершин вместо 1.4 млн — в 2300 раз меньше.
25. Почему сэмплирование не ломает обучение?
Потому что при правильном перевзвешивании оценка несмещённая. Точная сумма $e(v) = \sum_i w_i e(i)$ по $d$ соседям оценивается как $\hat e(v) = (d/S)\sum_{i \in \text{выборка}} w_i e(i)$, и математическое ожидание равно точному значению. Дисперсия есть, но это ровно та же ситуация, что при стохастическом градиентном спуске: шумный градиент по мини-батчу вместо точного. В замере [15,10,5] дало 99.3% качества полного графа.
26. Сэмплирование соседей или кластерное разбиение?
Сэмплирование — более безопасный дефолт: несмещённое, не требует подготовки, сразу учитывает новые рёбра. Кластерное разбиение быстрее на эпоху (12 мин против 21) и даёт 98.2% качества, но теряет 8.6% межкластерных рёбер, вносит смещение и требует рекластеризации при изменении графа. Разумно, когда граф стабилен, а обучение идёт часто.
27. Что происходит с новым объектом в LightGCN?
У него нет соседей, поэтому все слои распространения дают ноль: $e^{(1)} = e^{(2)} = e^{(3)} = 0$. Итоговый вектор равен $e^{(0)}/4$ — то есть необученному случайному шуму, поделённому на четыре. Recall на объектах моложе суток 0.008. Три лечения: проекция признаков вместо свободного $e^{(0)}$, виртуальные рёбра к вершинам-атрибутам, прогрев по формуле $w(n)=n/(n+n_0)$ из темы 6.3. Вместе дают 0.112 — рост в 14 раз.
28. Как обновлять графовую модель, не переобучая её каждый раз?
Ключевое наблюдение: обучаемые векторы слоя 0 меняются медленно, а структура графа — быстро. Пересчёт одного распространения по свежему графу со старыми $e^{(0)}$ стоит 4 минуты против 6 часов полного переобучения и даёт 97.4% качества. Это позволяет обновляться ежечасно. Плюс локальность: новое ребро при $K=3$ затрагивает около 25 тыс. вершин из 3.1 млн, то есть 0.8% графа — остальное пересчитывать не нужно.
29. Какая утечка специфична именно для графовых моделей?
Тестовые рёбра, оставшиеся в графе. Распространение проходит по такому ребру напрямую, и вектор пользователя буквально содержит вклад от объекта, который надо предсказать. Завышение почти втрое: 0.3184 против 0.1089. Ошибку легко сделать потому, что структура графа и обучающая выборка задаются раздельно — у матричной факторизации такого не бывает, там обучающая матрица и есть источник сигнала. Граф должен строиться только из рёбер до момента разделения.
30. Как понять, нужен ли граф вообще?
Четыре шага. ① Построить распределение степеней: весь выигрыш графа сосредоточен на разрежённых вершинах (+129% при степени 1–3, −0.8% при степени выше 100), и если медиана выше 30, граф даст мало. ② Посчитать PPR Монте-Карло — 40 минут без обучения. ③ Сравнить с item-item. ④ Если PPR не выиграл, граф задаче не помогает, и LightGCN тоже не поможет — он решает ту же задачу, просто дороже. Вкладываться в обучаемую графовую модель имеет смысл только после того, как PPR показал выигрыш.
