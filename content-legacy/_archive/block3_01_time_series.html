📈 Что такое задача прогнозирования ВР?
Временной ряд — последовательность наблюдений, упорядоченных во времени. Цель — предсказать будущие значения.

Задача: дано $y_1, y_2, \ldots, y_T$ — предсказать $y_{T+1}, \ldots, y_{T+h}$, где $h$ — горизонт прогноза.

Ключевое отличие от обычного ML: нельзя перемешивать данные — время имеет значение. Паттерны из прошлого помогают предсказывать будущее, но только если соблюдать хронологию.
🔍 Декомпозиция временного ряда
Любой ВР = Тренд + Сезонность + Остаток. Понять структуру ряда — первый шаг перед выбором модели.
Аддитивная декомпозиция
$$Y_t = T_t + S_t + R_t$$
$T_t$ (Trend) — долгосрочное направление. $S_t$ (Seasonal) — повторяющиеся паттерны. $R_t$ (Residual) — случайный шум.
🤏 На пальцах — аддитивная

Пример: продажи кофе в кафе.

🗓 Тренд: каждый год продаём на 5% больше — бизнес растёт.
📅 Сезонность: летом меньше горячего кофе, зимой больше — одинаковая разница каждый год.
💨 Остаток: случайный дождь в понедельник — неожиданный скачок.

Аддитивная: Продажи = 500 (тренд) + 50 (декабрь, +) + 20 (случайный дождь) = 570

Мультипликативная декомпозиция
$$Y_t = T_t \times S_t \times R_t$$
Используется когда амплитуда сезонности пропорциональна тренду. Пример: интернет-магазин — в 2019 продаёт 1000/мес, пик декабря +50% = +500. В 2023 продаёт 5000/мес, пик декабря +50% = +2500. Пик растёт вместе с трендом.
🤏 Аддитивная vs Мультипликативная — визуально

📊 Смотрим на график: если пики и провалы одинаковой высоты независимо от уровня тренда → аддитивная.
Если пики растут вместе с трендом (всё шире) → мультипликативная.
🛠 Лайфхак: log-трансформация $\ln(Y_t)$ превращает мультипликативную в аддитивную: $\ln(T\times S\times R) = \ln T + \ln S + \ln R$.

Визуальная схема декомпозиции (синтетический пример — 36 месяцев)

⏰ Когда и где применяется декомпозиция
  • EDA: первый шаг — понять, есть ли тренд/сезонность, прежде чем выбрать модель
  • STL (Seasonal-Trend decomposition using Loess) — стандарт в Python/R, устойчив к выбросам

⚖️ Стационарность
ARIMA требует стационарного ряда. Как проверить и исправить — базовый навык.
Определение стационарности
$$E[y_t] = \mu \quad \text{(постоянное среднее)}$$ $$\text{Var}[y_t] = \sigma^2 \quad \text{(постоянная дисперсия)}$$ $$\text{Cov}(y_t, y_{t-k}) = \gamma_k \quad \text{(зависит только от лага } k\text{, не от }t\text{)}$$
Слабая стационарность = выполнены все три условия. Строгая (сильная) = стационарны все моменты. На практике достаточно слабой.
🤏 На пальцах

Стационарный ряд — как шум вентилятора: всегда около одного среднего, одинаковая "громкость", одинаковые корреляции.

Нестационарный — как цена биткоина: среднее меняется (то 10К, то 60К), дисперсия тоже растёт. Паттерны из 2018 не помогают предсказывать 2021.

Суть: ARIMA ищет повторяющиеся паттерны. Они могут повторяться только если ряд "стабилен" (стационарен).

✅ Стационарный

Среднее ≈ const, дисперсия ≈ const

❌ Нестационарный (тренд)

Растущее среднее — ARIMA не работает

⚠️ Нестационарный (дисперсия)

Растущая дисперсия — GARCH / log-трансформация

🔧 После дифференцирования

$\Delta y_t = y_t - y_{t-1}$ убирает тренд

ADF-тест (Augmented Dickey-Fuller)
$$H_0: \text{ряд нестационарен (единичный корень)}$$ $$\Delta y_t = \alpha + \beta t + \gamma y_{t-1} + \sum_{i=1}^p \delta_i \Delta y_{t-i} + \varepsilon_t$$ $$\text{Тест-статистика: } \hat{\tau} = \frac{\hat{\gamma}}{SE(\hat{\gamma})}$$
$H_0$: γ=0 (единичный корень, нестационарен). Если p-value < 0.05 → отвергаем $H_0$ → ряд стационарен. В Python: from statsmodels.tsa.stattools import adfuller; adfuller(y).
🤏 На пальцах — ADF тест

ADF проверяет: "если я сдвину ряд на 1 шаг назад и вычту — получится стационарный или нет?". Формально: тестирует коэффициент при $y_{t-1}$ в регрессии. γ ≈ 0 → каждый лаг "тянет" ряд вверх → нестационарен (блуждание). γ < 0 → ряд "возвращается" к среднему → стационарен.

Правило: p < 0.05 → стационарен → можно ARIMA(p, d=0, q). p ≥ 0.05 → нужно дифференцировать ($d=1$).

Дифференцирование = "смотрим на изменения, а не на абсолютные значения". Параметр $d=1$ в ARIMA(p,1,q).

📐 ARIMA
AutoRegressive Integrated Moving Average — классический инструмент для стационарных/интегрированных рядов.
ARIMA(p, d, q) — три компонента
$$\underbrace{\phi(B)}_{\text{AR часть}}\underbrace{(1-B)^d}_{\text{I часть}} y_t = \underbrace{\theta(B)\varepsilon_t}_{\text{MA часть}}$$
AR(p): $y_t = \phi_1 y_{t-1} + \phi_2 y_{t-2} + \ldots + \phi_p y_{t-p} + \varepsilon_t$ — зависимость от прошлых значений.
I(d): $(1-B)^d y_t$ — дифференцирование $d$ раз для достижения стационарности.
MA(q): $y_t = \varepsilon_t + \theta_1\varepsilon_{t-1} + \ldots + \theta_q\varepsilon_{t-q}$ — зависимость от прошлых ошибок.
AR(p)

"Инерция" — завтра похоже на сегодня

$y_t = 0.8y_{t-1} + \varepsilon_t$

Примеры: температура, цены, курс валют

MA(q)

"Память об ошибках" — прошлые шоки влияют

$y_t = \varepsilon_t + 0.5\varepsilon_{t-1}$

Примеры: реакция рынка на новости

ARMA(p,q)

Комбинация: инерция + память об ошибках

$y_t = 0.7y_{t-1} + \varepsilon_t + 0.3\varepsilon_{t-1}$

Большинство реальных рядов

🤏 AR vs MA — аналогия

AR — "GPS-навигатор": смотрит на предыдущие позиции и экстраполирует. Продажи вчера 100, позавчера 90 → завтра ≈ 110.

MA — "Официант с памятью": если час назад было неожиданно много гостей (ошибка прогноза), учитывает это в следующем часу. Не помнит абсолютных значений — помнит только "сюрпризы".

Пошаговый выбор параметров ARIMA
Методология Box-Jenkins — как выбрать p, d, q
1

Проверяем стационарность → выбираем d

ADF-тест. p-value > 0.05 → дифференцировать (d=1). Повторяем до стационарности. Обычно d=0 или d=1.

2

Строим ACF (Autocorrelation Function) → выбираем q

Если ACF резко обрывается на лаге q → MA(q). Лаги выше q → незначимы (в полосе ±1.96/√n).

3

Строим PACF (Partial Autocorrelation Function) → выбираем p

Если PACF резко обрывается на лаге p → AR(p). Лаги выше p → незначимы.

4

Сравниваем несколько моделей по AIC/BIC → финальный выбор

AIC = 2k − 2ln(L̂). Меньше = лучше. auto_arima() делает это автоматически.

5

Диагностика остатков

Остатки должны быть белым шумом: нет автокорреляции (Ljung-Box тест), нормальное распределение.

⏰ Когда использовать ARIMA
  • Хорошо: один ряд с достаточной историей (100+ точек), нет явных внешних факторов
  • Хорошо: финансовые ряды (возвраты акций), данные без выраженных праздников
  • Плохо: множество рядов (5M SKU — слишком медленно), явные праздники, нелинейные паттерны
  • Альтернатива: при сезонности → SARIMA. При внешних регрессорах → ARIMAX. При множестве рядов → LightGBM global model
🔮 Facebook (Meta) Prophet
Аддитивная модель с явными компонентами тренда, сезонности и праздников. Не требует стационарности.
Модель Prophet
$$y(t) = g(t) + s(t) + h(t) + \varepsilon_t$$
$g(t)$ — тренд: либо piecewise-linear, либо logistic growth (с насыщением).
$s(t)$ — сезонность через ряды Фурье (годовая + недельная + дневная).
$h(t)$ — праздники (holiday effects) — явно заданные пользователем.
$\varepsilon_t$ — шум.
Сезонность через ряды Фурье
$$s(t) = \sum_{n=1}^{N}\!\left(a_n\cos\!\frac{2\pi n t}{P} + b_n\sin\!\frac{2\pi n t}{P}\right)$$
$P$ — период (365.25 для годовой, 7 для недельной). $N$ — число гармоник (Prophet default: N=10 годовая, N=3 недельная). Параметры $a_n, b_n$ обучаются из данных. Больше N → более гибкая сезонность, но риск overfitting.
🤏 Ряды Фурье — зачем синусы?

Любую периодическую функцию можно разложить в сумму синусов и косинусов (теорема Фурье). Первая гармоника ($n=1$) — базовая "волна" с периодом P. Вторая ($n=2$) — удвоенная частота, детали. И так далее.

Аналогия: звук гитарной струны = основная нота + обертоны. Сезонность = основной цикл + детальные поднастройки. Больше гармоник → точнее форма сезонности.

Как гармоники складываются в сезонность
N=1 (грубо) → N=3 (лучше) → N=10 (детально)
Piecewise Linear тренд с changepoints
$$g(t) = (k + \mathbf{a}(t)^T\!\boldsymbol{\delta})\,t + (m + \mathbf{a}(t)^T\!\boldsymbol{\gamma})$$
$k$ — базовый наклон. $\boldsymbol{\delta}$ — корректировки наклона в changepoints. $\mathbf{a}(t)$ — индикаторная функция (в каком сегменте мы). Prophet автоматически находит changepoints — точки, где тренд меняет направление. Обнаруживает, например, момент запуска нового продукта или кризис.
🤏 Changepoints на пальцах

Представь рост пользователей Twitter: 2008–2012 — стремительный рост, 2016 — плато, 2022 — резкое падение после покупки Маском. Один глобальный тренд такое не опишет. Prophet делит тренд на отрезки — в каждом свой наклон. Переломы (changepoints) он находит автоматически по данным.

Lag features
$$x_t^{(k)} = y_{t-k}, \quad k \in \{1, 7, 14, 30, 365\}$$
Лаги выбираем на основе ACF: если ACF значимо на лагах 1, 7, 30 → включаем lag_1, lag_7, lag_30. Лаг-7 = "неделю назад" захватывает недельную сезонность без явного seasonality компонента.
🤏 На пальцах

Хочешь предсказать продажи в следующий понедельник? Дай модели: продажи прошлого понедельника (lag_7), позапрошлого (lag_14), месяц назад (lag_30), год назад (lag_365). Модель сама выучит "в понедельник обычно продаём столько сколько в прошлый понедельник ± X".

Rolling window features
$$\bar{y}^{(k)}_t = \frac{1}{k}\sum_{i=1}^{k} y_{t-i}$$ $$\sigma^{(k)}_t = \sqrt{\frac{1}{k-1}\sum_{i=1}^{k}\!\left(y_{t-i} - \bar{y}^{(k)}_t\right)^2}$$
Rolling mean сглаживает шум → плавный тренд. Rolling std = волатильность (нестабильность). Ещё: rolling max/min (сигнал "был ли резкий всплеск?"), rolling median (устойчив к выбросам).
🤏 На пальцах

Rolling mean за 7 дней = "какова средняя температура за последнюю неделю?" — не нужно смотреть на каждый день. Rolling std = "насколько нестабильна была неделя?" — если std высокий, всё скачет, значит что-то необычное.

Calendar / синусно-косинусное кодирование
$$x_{\sin} = \sin\!\left(\frac{2\pi \cdot \text{dow}}{7}\right), \quad x_{\cos} = \cos\!\left(\frac{2\pi \cdot \text{dow}}{7}\right)$$
Проблема: если кодировать день недели числом 1–7, то воскресенье (7) "далеко" от понедельника (1) — нарушается периодичность. Sin/cos "замыкают" неделю в круг: 0 → 2π. Для tree models (LightGBM) подойдёт и прямое число — деревья могут сами найти разрыв.
Синусно-косинусное кодирование дня недели
Пн(0) и Вс(6) должны быть "близко" — sin/cos это обеспечивает
⏰ Когда ML-подход лучше ARIMA/Prophet
  • Много рядов: одна global LightGBM на 5M SKU против 5M ARIMA-моделей
  • Внешние признаки важны: цена конкурентов, погода, маркетинговые расходы — всё как feature
  • Нелинейные паттерны: "при скидке > 30% AND праздник → продажи ×5" — деревья легко справятся
  • Примеры: Amazon demand forecasting (DeepAR), Walmart M5 competition (LightGBM выиграл), Uber surge (gradient boosting)
✅ Walk-Forward Validation
Единственно честный способ оценить модель ВР. Random split = утечка данных.
Схема Walk-Forward CV
$$\text{Fold } k: \;\; \text{Train}=[1,\,t_k], \quad \text{Test}=[t_k+1,\,t_k+h]$$
Каждый fold сдвигается вперёд на $h$ (горизонт прогноза). Модель ВСЕГДА обучается только на прошлом, тестируется только на будущем. Число фолдов = (T - initial_train) / h.
🤏 Почему Random Split — смерть для ВР

Строим модель продаж. Лаговый признак lag_7 для test-точки "сентябрь 2024" требует данных из "августа 2024". При random split "август 2024" может оказаться в train — тогда модель вычисляет lag_7 корректно. Но в production мы предсказываем будущее — там этих данных не было бы при обучении.

Результат: lab AUC/RMSE отличный, production RMSE в 2-3 раза хуже. Walk-forward честно симулирует production-среду.

📏 Метрики качества прогноза
Разные метрики для разных бизнес-задач. Нельзя использовать MSE как для классификации.
Основные метрики
$$\text{MAE} = \frac{1}{n}\sum_{t=1}^n |y_t - \hat{y}_t|$$ $$\text{RMSE} = \sqrt{\frac{1}{n}\sum_{t=1}^n (y_t - \hat{y}_t)^2}$$ $$\text{MAPE} = \frac{100\%}{n}\sum_{t=1}^n \frac{|y_t - \hat{y}_t|}{y_t}$$ $$\text{SMAPE} = \frac{200\%}{n}\sum_{t=1}^n \frac{|y_t - \hat{y}_t|}{|y_t| + |\hat{y}_t|}$$
MAPE нельзя считать при $y_t \approx 0$ (деление на ноль). SMAPE решает эту проблему. WAPE = $\sum|y-\hat{y}|/\sum y$ — взвешенный MAE, хорош при разных масштабах.

🏬 Amazon · Supply Chain Forecasting

DeepAR: нейросетевой прогноз для 400M+ SKU

Задача: прогнозировать спрос на 400M+ SKU по всему миру. Стандартный ARIMA — нереально: 400M моделей, холодный старт для новых товаров, нет crosslearning.

  • DeepAR (Amazon Research, 2020): рекуррентная нейросеть (LSTM), обученная глобально на всех SKU. Каждый SKU — один "example" в обучении. Глобальная модель разделяет веса → знания о сезонности переносятся между SKU.
  • Probabilistic forecasting: вместо точечного прогноза → распределение. P10/P50/P90 → гибкое управление запасами.
  • Cold start: новый SKU без истории — модель использует static features (категория, цена, описание) и "похожие" паттерны из обученных рядов.
  • Результат: ~15% снижение out-of-stock при снижении overstock на ~10% по сравнению с ensemble ARIMA.

Ключевые решения Amazon:
1. Иерархическое согласование (MinT): прогнозы SKU должны суммироваться в региональные, те — в глобальные. MinT (Minimum Trace) reconciliation: находит взвешенную комбинацию прогнозов всех уровней иерархии для минимизации суммарной дисперсии ошибок.
2. Quantile loss: для P10/P50/P90 обучают модель с pinball loss: $L_\alpha = \alpha\max(y-\hat{y}, 0) + (1-\alpha)\max(\hat{y}-y, 0)$. P90 используется для safety stock (консервативно), P50 для baseline.
3. Feature engineering: признаки-"индикаторы событий": ближайший Prime Day, Black Friday, локальные праздники — добавляются как binary/distance features к каждой точке ряда.

❓ Q&A — 10 вопросов
▶Что такое стационарность и почему ARIMA требует её? популярный
Стационарность: среднее, дисперсия и автоковариация ряда не меняются со временем.

Почему нужна для ARIMA: ARIMA ищет устойчивые паттерны (AR- и MA-коэффициенты), которые одинаковы во всех периодах. Для нестационарного ряда паттерны меняются — в 2020 среднее одно, в 2023 — другое. Модель, обученная на 2020, будет плохо работать в 2023.

Проверка: ADF-тест (p < 0.05 → стационарен). Визуально: нет явного тренда, постоянная дисперсия.

Решение при нестационарности: дифференцирование (параметр d). Цена акции — нестационарна. Логарифмические возвраты (log returns) — стационарны.
▶Как выбрать параметры p, d, q для ARIMA? практика
d: ADF-тест. p ≥ 0.05 → дифференцировать. Применяем столько раз, пока p < 0.05. Обычно d=0 или d=1.

p (AR порядок): PACF-график. Находим лаг, после которого PACF резко обрывается (в зону незначимости ±1.96/√n). p = этот лаг.

q (MA порядок): ACF-график. Находим лаг, после которого ACF резко обрывается. q = этот лаг.

Автоматически: from pmdarima import auto_arima; auto_arima(y, stepwise=True) перебирает комбинации и выбирает по AIC.

Практика: для большинства экономических рядов ARIMA(1,1,1) или ARIMA(0,1,1) — хорошая отправная точка.
▶В чём Prophet лучше ARIMA и когда его использовать? сравнение
Prophet выигрывает:
1. Нет требования стационарности
2. Автоматически обрабатывает праздники и события (holidays параметр)
3. Обнаруживает changepoints в тренде
4. Устойчив к пропускам и выбросам
5. Выдаёт интерпретируемые компоненты (тренд + сезонность отдельно)

ARIMA выигрывает:
1. Теоретически строгий для стационарных рядов
2. Лучше для финансовых данных без выраженной сезонности
3. Быстрее для одного ряда

Когда Prophet: бизнес-показатели (выручка, DAU), сезонные ряды с праздниками, когда нужна интерпретация компонентов.
▶Почему нельзя random split для ВР? популярный
Лаговые признаки создают "зависимость от будущего" при random split:

Пример: предсказываем продажи в день T. Признак lag_7 = продажи в день T-7. При random split день T-7 может попасть в test, а день T — в train. Тогда при вычислении lag_7 для train-точки T мы используем значение из test.

Это leakage: модель обучается "зная" будущие тестовые данные.

Walk-forward (правильно): train всегда строго раньше test по времени. Симулирует реальный deployment.
▶Что такое lag leakage и как его избежать? deep dive
Lag leakage: при создании признаков лаги вычисляются неправильно — включают данные из будущего.

Примеры:
1. Lag_1 для предсказания t+1 вычисляется от "сегодня" вместо "вчера"
2. Rolling mean за 7 дней для точки T включает данные из T+1..T+3 (если неправильно сдвинуть)
3. Признак "выручка за следующую неделю" (явная утечка будущего)

Как избежать:
- Для предсказания горизонта h: все признаки должны быть из периода ≤ T (не T+1 и далее)
- Использовать df.shift(1) в pandas при создании лагов
- Писать unit-тесты на датасет: проверять что нет корреляции признаков с "будущим таргетом"
- Строгий temporal join при создании датасета
▶Что такое иерархическое согласование прогнозов? deep dive
В ритейле прогнозы должны быть согласованы: сумма прогнозов по SKU = прогноз по категории = прогноз по магазину = общий прогноз.

Подходы:
1. Bottom-Up: суммируем прогнозы SKU → категории → итого. Точен на нижнем уровне, но ошибки SKU накапливаются.
2. Top-Down: прогнозируем на верхнем уровне, делим вниз пропорционально историческим долям. Теряет точность SKU.
3. MinT (Minimum Trace, Wickramasuriya et al., 2019): находит оптимальную матрицу P для взвешивания прогнозов всех уровней. Минимизирует суммарную дисперсию ошибок по иерархии. Используется в Amazon, Walmart.

В Python: пакет hierarchicalforecast (Nixtla).
▶Как строить доверительные интервалы для прогноза? практика
Точечный прогноз недостаточен для принятия решений (управление запасами, provisioning).

Методы:
1. ARIMA CI: аналитически из дисперсии ошибки. Расширяется с горизонтом: $\sigma_h^2 = \sigma^2(1 + \sum_{i=1}^{h-1}\psi_i^2)$.
2. Quantile regression: LightGBM с quantile loss. Обучаем три модели: α=0.1, 0.5, 0.9 → получаем P10/P50/P90.
3. Conformal prediction: используем остатки из holdout для построения адаптивных PI. Гарантированное покрытие без предположений о распределении.
4. Bootstrap: генерируем 1000 версий ряда, добавляя случайные residuals → CI из квантилей ансамбля.

Практика Amazon/Uber: P90 для "консервативного" решения (overstock лучше чем outage), P50 для baseline.
▶Что такое intermittent demand и как с ним работать? практика
Intermittent (sporadic) demand: товар продаётся редко, много нулей в ряду. Типично для: запчасти, промышленное оборудование, медицинские расходники.

Метрики ADI и CV²:
- ADI (Average Demand Interval) = средний интервал между ненулевыми продажами
- CV² = (std нулевых продаж)² / (mean нулевых продаж)²
По матрице ADI × CV² классифицируем ряд: smooth, erratic, intermittent, lumpy.

Методы:
1. Croston's method: раздельно моделирует интервал и размер события
2. Zero-inflated Poisson/NegBin: смешанная модель P(y=0) + distribution(y>0)
3. Temporal aggregation: еженедельные/месячные данные — меньше нулей
▶Как выбрать между ARIMA, Prophet и ML (LightGBM) для конкретной задачи? популярный
Один ряд + нет выраженных праздников + короткая история: ARIMA
Бизнес-KPI с праздниками + нужна интерпретация: Prophet
Много рядов (100+) + есть внешние признаки: LightGBM global model
Сложные нелинейные паттерны + много данных: DeepAR/N-BEATS (нейросети)

Практическое правило: начинать с простых baseline (naive, seasonal naive, moving average), потом Prophet/ETS, потом ML. Если ML даёт <10% улучшения над Prophet — Prophet достаточен.

Ensemble: лучший результат обычно у ансамбля из 3-5 моделей. Amazon, Netflix, Walmart используют weighted ensemble.
▶Какие метрики использовать для оценки прогнозов? популярный
MAPE: процентная ошибка — понятна бизнесу ("ошибаемся на 8%"). Нельзя при y≈0.
SMAPE: симметричный MAPE, решает проблему нулей. Используется в M-competition.
RMSE: штрафует крупные ошибки сильнее — если outage критичен, RMSE важнее MAE.
WAPE = Σ|e|/Σy: взвешенный MAE. Стандарт в ритейле — крупные SKU важнее мелких.
Bias = Σ(ŷ-y)/Σy: систематическое занижение/завышение. Для WMS bias > 0 (overforecast) лучше чем bias < 0 (underforecast → stockout).

Правило: всегда считать несколько метрик + отдельно по категориям, горизонтам, периодам. Одна метрика — недостаточно.
