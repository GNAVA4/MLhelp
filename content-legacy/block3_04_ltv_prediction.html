💰 Что такое LTV / CLV
Customer Lifetime Value — суммарная прибыль, которую клиент принесёт за всё время взаимодействия с компанией.

LTV (Lifetime Value) = CLV (Customer Lifetime Value) — одна и та же метрика. Ответ на вопрос: "сколько стоит этот клиент?". Определяет сколько можно потратить на привлечение (CAC) и удержание.

3×
Правило: LTV/CAC > 3 для здорового бизнеса
5-7×
Дороже привлечь нового vs удержать существующего клиента
20%
Топ 20% клиентов генерируют 80% выручки (Парето)
12 мес
Типичный горизонт для 1-year LTV прогноза

Зачем предсказывать LTV? Не все клиенты одинаково ценны. Зная будущий LTV в момент регистрации (или после первой покупки) — компания может персонализировать маркетинг, предложить правильные скидки, сосредоточить поддержку на VIP-клиентах.

🎯
Acquisition

Bid больше за ценных пользователей в рекламе. Google/Facebook: передать LTV → оптимизировать под Value, не CPA

🔄
Retention

Высокий LTV + риск оттока = приоритет для winback кампании. Низкий LTV + риск оттока = пусть уходит

💎
Segmentation

VIP-программы, персональные менеджеры, бесплатная доставка — только для top-10% по LTV

📐 Базовые формулы CLV
От простой исторической формулы к вероятностным моделям.
Историческая CLV (простейшая)
$$\text{Historical CLV} = \sum_{t=1}^{T} (\text{Revenue}_t - \text{Cost}_t)$$
Просто сумма всех прошлых прибылей. Смотрим назад. Полезно для сегментации и анализа, но не для прогноза будущего.
Predictive CLV с дисконтированием (стандарт для финансов)
$$\text{CLV} = \sum_{t=1}^{T} \frac{m_t \cdot r_t}{(1+d)^t}$$
$m_t$ — маржа (margin) в период $t$.
$r_t$ — вероятность что клиент "живой" в период $t$ (retention probability, $r_t = r^t$ при постоянном retention).
$d$ — ставка дисконтирования (discount rate). Деньги сегодня дороже денег завтра.
При постоянных $m$ и $r$: $\text{CLV} = m \cdot \frac{r}{1+d-r}$ — геометрическая прогрессия.
🤏 Зачем дисконтирование?

1000₽ через год ≠ 1000₽ сегодня. При ставке дисконтирования d=10%: 1000₽ через год = 1000/1.1 = 909₽ сегодня. Через 5 лет = 1000/1.1⁵ = 621₽. Деньги далёкого будущего менее ценны.

Для CLV: клиент с $100/год в течение 10 лет ≠ 1000$ CLV. При d=10%: CLV = 100/1.1 + 100/1.1² + ... = $614. Это реальная NPV (Net Present Value) клиентского потока.

🔢 Простой расчёт CLV для SaaS компании
Дано
Подписка 1000₽/мес. Churn rate = 5%/мес → retention = 95%. Маржа = 60%. Ставка дисконтирования = 12%/год = 1%/мес.
Формула
$m = 1000 \times 0.6 = 600₽/мес$. $r = 0.95$. $d = 0.01$. $\text{CLV} = 600 \times \frac{0.95}{1.01 - 0.95} = 600 \times \frac{0.95}{0.06} = 600 \times 15.83 = \mathbf{9{,}500₽}$
Средняя жизнь клиента
$\text{ALT} = 1/(1-r) = 1/0.05 = 20$ месяцев. $\text{CLV} \approx m \times \text{ALT} = 600 \times 20 = 12{,}000₽$ (без дисконтирования). С дисконтированием — 9,500₽.
Решение
CAC должен быть < 9,500/3 = 3,167₽ для сохранения LTV/CAC ≥ 3. Если CAC = 5,000₽ → бизнес убыточен или нужно снизить churn.
🎲 BG/NBD Model (Beta-Geometric / Negative Binomial Distribution)
Вероятностная модель для non-contractual settings: нет подписки, клиент может "умереть" (уйти) незаметно в любой момент.

Контекст: интернет-магазин, кофейня, авиакомпания. Клиент не говорит "я ухожу". Просто перестаёт покупать. Когда он "мёртв"? Когда "просто не купил пока"? BG/NBD отвечает на этот вопрос.

💡
Ключевое предположение BG/NBD: пока клиент "жив" — совершает покупки согласно Poisson(λ). В случайный момент "умирает" согласно Geometric(p). Мы не наблюдаем момент смерти — только покупки.
BG/NBD — 4 предположения модели
1. Транзакции: пока клиент жив — покупает со скоростью λ (Poisson). Количество покупок за T = Poisson(λT).
2. Смерть: после каждой покупки клиент "умирает" с вероятностью p (Geometric drop-out). Отсюда: "B" = Beta-Geometric.
3. Гетерогенность λ: у разных клиентов разный λ. Популяционное распределение: $\lambda \sim \text{Gamma}(r, \alpha)$. Отсюда: "NBD" = Negative Binomial.
4. Гетерогенность p: $p \sim \text{Beta}(a, b)$ — разные клиенты по-разному склонны уходить.
Параметры $r, \alpha, a, b$ оцениваются MLE по исторической RFM-истории клиентов. После подгонки — модель предсказывает P(alive) и ожидаемое количество будущих покупок для каждого клиента.
BG/NBD — ключевые формулы
$$P(\text{X=x} | \text{alive}) = \text{Poisson}(\lambda t) \cdot P(\text{alive})$$ $$E[\text{покупок} | x, t_x, T] = \frac{r+x}{\alpha + T} \cdot \frac{1}{1 + \frac{a}{b+x-1}\left[\frac{\alpha+T}{\alpha+t_x}\right]^{r+x}}^{-1}$$
$x$ — количество покупок в наблюдаемом периоде. $t_x$ — время последней покупки. $T$ — общая длина наблюдаемого периода.
На практике используем Python библиотеку lifetimes: from lifetimes import BetaGeoFitter. Подгонка: bgf.fit(df['frequency'], df['recency'], df['T']). Прогноз: bgf.predict(t=52, frequency, recency, T).
🤏 BG/NBD на пальцах

Два клиента. Клиент А: 10 покупок за год, последняя неделю назад. Клиент Б: 10 покупок за год, последняя 11 месяцев назад.

По frequency (10 покупок) они одинаковые. Но по recency — очень разные. Клиент А скорее всего жив. Клиент Б — может быть "мёртв" (ушёл к конкурентам).

BG/NBD формализует это: P(alive|А) ≈ 0.95, P(alive|Б) ≈ 0.15. Прогноз покупок через год: А → 9.1, Б → 0.8. Это и есть вклад в CLV!

🔢 Пошаговый расчёт P(alive) для клиента Глеб (x=1, t_x=4, T=52)

Глеб купил 1 раз в начале года (t_x=4 нед) и больше не появлялся. 48 недель тишины. Жив?

Интуиция
48 недель без покупок при λ≈r/α=0.055 в неделю → если живой, ожидаемо 48×0.055=2.6 покупки за это время. Ноль покупок за 2.6 ожидаемых → P(живой) × P(0 покупок | живой) = P(живой) × e^{-2.6} ≈ P(живой) × 0.074.
Баланс
P(alive) vs P(dead): $\frac{P(\text{alive} \cap 0\text{ after } t_x)}{P(\text{dead after }t_x)} = \frac{e^{-\lambda(T-t_x)}}{p} \approx \frac{0.074}{p}$. При высоком p (склонность к уходу) → знаменатель большой → P(alive) мала. Параметры a=0.793, b=2.426 → E[p] = a/(a+b) ≈ 0.25. P(alive|Глеб) ≈ 0.11.
Итог
P(alive) = 11% → Ожидаем 0.11 × E[λ] × 52 нед = 0.11 × 0.055 × 52 ≈ 0.31 покупки в следующий год. При среднем чеке 5000₽: CLV = 0.31 × 5000 × маржа60% = 930₽.
Сравнение
Жанна: x=12, t_x=51 → P(alive)=0.97, E[покупок]=10.8. CLV = 10.8 × 2800 × 60% = 18,144₽. Разница в 19 раз! BG/NBD точно захватывает эту разницу.

📊 Pareto/NBD vs BG/NBD
Оригинальная модель (Schmittlein et al., 1987) и её упрощение (Fader et al., 2005). В чём разница?

Pareto/NBD — идея модели
$$\lambda \sim \text{Gamma}(r, \alpha), \quad \mu \sim \text{Gamma}(s, \beta)$$ $$\text{Lifetime} = \text{Exp}(\mu) \quad \text{(непрерывный "уход")}$$
$\lambda$ — скорость покупок (Poisson rate). $\mu$ — скорость ухода (hazard rate "умирания"). Оба гетерогенны в популяции через Gamma-миксчер.
Pareto в названии: Gamma(s,β) × Exponential = Pareto distribution для lifetime. При s=1: Exponential lifetime = "нет памяти".
Точность vs BG/NBD: Fader et al. (2005) показали: BG/NBD имеет практически идентичную точность при значительно более простой реализации. На большинстве датасетов разница <1% MAE.
💵 Gamma-Gamma Model — монетизация
BG/NBD предсказывает количество покупок. Gamma-Gamma предсказывает среднюю стоимость покупки.
Gamma-Gamma Model
$$E[M | \bar{m}, x] = \frac{p \cdot \gamma + x \cdot \bar{m}}{p \gamma + x}$$
$\bar{m}$ — средняя стоимость транзакции клиента. $x$ — количество транзакций. $p, q, \gamma$ — параметры модели.
Предположение: стоимость транзакции $\sim \text{Gamma}(p, v)$, а $v \sim \text{Gamma}(q, \gamma)$ по клиентам.
Shrinkage: оценка = взвешенное среднее между "персональной историей" ($\bar{m}$) и "популяционным средним" ($\gamma/p$). Клиенты с малым количеством транзакций сильнее тянутся к среднему.
🤏 Gamma-Gamma — зачем нужен shrinkage

Новый клиент купил 1 раз на 50,000₽. Его "средний чек" = 50,000₽. Достоверно ли это? Нет — одна покупка.

Gamma-Gamma: E[M|50000, x=1] = (p×γ + 1×50000)/(p×γ+1). При популяционном среднем 3,000₽: оценка ≈ (0.5×3000 + 50000)/1.5 ≈ 34,333₽. "Сдвинулись" к средней — мы не уверены в одной наблюдении.

При x=100 транзакций по 50,000₽: shrinkage почти исчезает → E[M] ≈ 50,000₽. Статистически убедительно.

🔢 Итоговый CLV = BG/NBD × Gamma-Gamma × Discount
Шаг 1: BG/NBD
Для клиента Диана (x=6, t_x=46, T=52): E[покупок | следующий год] = 5.5 покупки. P(alive) = 0.88.
Шаг 2: Gamma-Gamma
Исторический средний чек Дианы = 1,500₽. x=6. E[M|1500, 6] = (p×γ + 6×1500)/(p×γ+6) ≈ 1,480₽ (shrinkage небольшой при 6 транзакциях).
Шаг 3: Маржа и дисконт
Маржа = 40%. Ставка дисконтирования = 10%/год. Поправочный коэффициент ≈ 0.92 (за год с равномерными покупками).
Итог
$\text{CLV}_{\text{1yr}} = 5.5 \times 1{,}480 \times 0.40 \times 0.92 = \mathbf{2{,}993₽}$. В Python: ggf.customer_lifetime_value(bgf, frequency, recency, T, monetary_value, time=1, discount_rate=0.10)
🤖 ML подходы к LTV Prediction
Когда BG/NBD недостаточен: богатые признаки, сложные паттерны — переходим к gradient boosting.

BG/NBD использует только RFM (Recency, Frequency, Monetary, T). Но у нас есть: поведенческие данные, engagement, канал привлечения, демография, продуктовые действия. ML использует всё это.

Two-stage LTV Model (Google, 2019)
$$\text{LTV} = P(\text{convert}) \times E[\text{value} | \text{convert}]$$ $$\text{Stage 1: } P(\text{convert}) = \sigma(\text{LGBM}(X))$$ $$\text{Stage 2: } E[\text{value} | \text{convert}] = \text{LGBM\_regressor}(X)$$
Мотивация: LTV-распределение — смесь точечной массы в 0 (клиент не купил) и непрерывного распределения для тех кто купил. Одна регрессия плохо это моделирует.
Stage 1: классификатор предсказывает вероятность хотя бы одной покупки в горизонте. Stage 2: регрессор предсказывает суммарную стоимость условно на покупку. LTV = произведение.
Google использует этот подход для Value-Based Bidding в Google Ads.
🤏 Почему Two-stage лучше одной регрессии при нулях

Задача: предсказать LTV за год. 70% пользователей — 0₽ (не купили ни разу). 30% — от 100₽ до 100,000₽.

Одна регрессия: средний LTV = 0.3 × E[value|buyer] ≈ 5,000₽. Предсказывает около 5,000 для всех. RMSE высокий, интерпретация неясна.

Two-stage: Stage 1 классифицирует 70% в "не купит". Stage 2 качественно предсказывает распределение для 30% покупателей. Итоговое LTV = P×E[V] — точнее, интерпретируемее, удобнее для принятия решений.

⭐ CLV как North Star Metric
Почему ведущие компании переходят от Revenue к CLV как ключевой метрике бизнеса.

North Star Metric — единственная метрика, вокруг которой выстраивается вся компания. Что лучше: выручка, MAU, NPS или CLV?

❌ Проблемы с Revenue как North Star
  • Краткосрочная: большие скидки = высокая выручка, но PLV = 0
  • Поощряет дешёвых клиентов наравне с VIP
  • Не учитывает CAC: дорого привлечённый клиент = убыток
  • Не предсказывает будущее: разовый всплеск vs устойчивый рост
✅ CLV как North Star
  • Long-term: оптимизирует весь жизненный цикл клиента
  • Учитывает CAC: LTV/CAC ≥ 3 = здоровый бизнес
  • Сегментирует: ресурсы → туда где наибольший LTV потенциал
  • Предиктивен: предсказанный CLV = leading indicator будущей выручки
🎵 Spotify · CLV как North Star (2022)

Переход от MAU к "Quality User" метрике на базе CLV

  • Проблема: MAU (Monthly Active Users) поощрял количество, не качество. Привлечение бесплатных пользователей которые никогда не конвертируются = расход маркетинга впустую.
  • Решение: "Adjusted Quality Score" = P(convert to Premium) × E[LTV | Premium]. Маркетинговые кампании оцениваются по AQS, не по MAU.
  • Результат: premium conversion rate вырос на 12% за год. CAC снизился на 18%.
  • Инструмент: BG/NBD на транзакционных данных Premium подписок + LightGBM для P(convert) с поведенческими признаками (listening time, playlist saves, social features).
🛍️ Amazon Prime · CLV-driven все решения

Почему Prime стоит $139/год и всё равно прибылен

  • CLV Prime vs non-Prime: исследование (Consumer Intelligence Research Partners): Prime member тратит $1,400/год vs $600 для non-Prime. Разница = $800/год. При марже 10% = $80/год дополнительной прибыли.
  • Маркетинг: Prime членство = CAC-агрегатор. $139/год membership fee ≈ стоимость привлечения → Amazon платит нулевой дополнительный CAC за высокоценного клиента.
  • LTV сегментация: Prime → бесплатная доставка (retention), эксклюзивные скидки, Prime Video (engagement). Всё для максимизации CLV.
  • Метрика команд: инженерные команды Amazon оцениваются по incremental CLV их фичей. A/B тест: "новая фича увеличивает CLV segment A на 3%?" → шипим.

❓ Q&A — 12 вопросов
▶Что такое CLV и зачем его предсказывать? популярный
CLV (Customer Lifetime Value) = суммарная чистая прибыль от клиента за всё время взаимодействия.

Зачем предсказывать:
1. CAC обоснование: тратить на привлечение ≤ CLV/3. Без CLV не знаем допустимый CAC.
2. Сегментация: VIP-клиенты (топ-10% CLV) требуют других стратегий чем массовый сегмент.
3. Marketing bid optimization: Google/FB Value-Based Bidding — платить больше за пользователей с высоким predicted CLV.
4. Product prioritization: фичи которые увеличивают CLV high-value сегмента = высокий приоритет.
5. Retention targeting: высокий CLV + высокий churn risk = первый приоритет для retention кампании.
▶Что такое BG/NBD и как работает? популярный
BG/NBD = Beta-Geometric / Negative Binomial Distribution. Вероятностная модель для предсказания будущих покупок в non-contractual settings (интернет-магазин, кофейня).

Предположения:
1. Пока живой → покупает по Poisson(λ)
2. После каждой покупки может "умереть" с вероятностью p (Geometric)
3. λ ~ Gamma(r,α) по клиентам (NBD часть)
4. p ~ Beta(a,b) по клиентам (BG часть)

Входные данные: только RFM — Frequency, Recency, T (длина наблюдаемого периода).

Выходные данные: P(alive), E[покупок за следующие T недель].

В Python: from lifetimes import BetaGeoFitter; bgf.fit(frequency, recency, T); bgf.predict(52, frequency, recency, T)
▶В чём разница BG/NBD и Pareto/NBD? deep
Pareto/NBD (1987): клиент может "умереть" в любой момент времени (continuous dropout). Lifetime ~ Exponential(μ). Теоретически более правдоподобен — уход происходит не только сразу после покупки.

BG/NBD (2005): клиент может "умереть" только сразу после покупки (discrete Geometric). Упрощение которое даёт практически идентичные результаты.

На практике: Fader et al. (2005) показали: MAE обеих моделей различается <1% на стандартных датасетах. BG/NBD значительно проще реализовать и оценить параметры (MLE сходится быстрее).

Выбор: в большинстве задач — BG/NBD. Для банков и академических работ — Pareto/NBD из-за более "правдоподобного" механизма ухода.
▶Что такое Gamma-Gamma модель? практика
Gamma-Gamma — дополнение к BG/NBD для моделирования суммы транзакции.

BG/NBD предсказывает количество покупок. Но CLV = количество × стоимость. Gamma-Gamma моделирует стоимость.

Идея: стоимость транзакции ~ Gamma(p, v) где v ~ Gamma(q,γ) по клиентам. Оценка через shrinkage:
$E[M | \bar{m}, x] = \frac{p\gamma + x\bar{m}}{p\gamma + x}$

Shrinkage: при малом x (мало покупок) → тянемся к популяционному среднему. При большом x → верим персональной истории.

Python: from lifetimes import GammaGammaFitter; ggf.fit(frequency, monetary_value); ggf.customer_lifetime_value(bgf, frequency, recency, T, monetary_value)
▶Когда ML лучше чем BG/NBD для предсказания LTV? популярный
ML (LightGBM) лучше когда:
1. Богатые признаки: engagement, поведение на сайте, продуктовые события, email-активность
2. Нелинейные взаимодействия важны (CLV сильно зависит от комбинации источника + поведения + демо)
3. Короткие горизонты прогноза (7-90 дней) — ML использует последние сигналы лучше
4. Contractual business (SaaS) — нет "незаметной смерти", есть явный чurn момент

BG/NBD лучше когда:
1. Только транзакционные данные доступны (RFM)
2. Нужна интерпретируемость: P(alive) понятна бизнесу
3. Длинные горизонты прогноза (3-5 лет)
4. Non-contractual FMCG — классическая область применения

Лучший результат: гибридный подход — BG/NBD P(alive) + expected_frequency как признаки для LightGBM.
▶Что такое LTV/CAC и почему он должен быть > 3? популярный
CAC = Customer Acquisition Cost = сколько стоит привлечь одного клиента.
LTV/CAC = соотношение ценности к стоимости привлечения.

Почему LTV/CAC > 3:
- Платим CAC сейчас, LTV получаем в будущем (time value of money)
- Есть overhead: customer service, infrastructure, product development не включены в CAC
- Нужен запас для экспериментов, маркетинговых промахов

Бенчмарки:
- LTV/CAC < 1: убыточно, сжигаем деньги
- LTV/CAC 1-3: не устойчиво или инвестиционная фаза роста
- LTV/CAC 3-5: хороший здоровый бизнес
- LTV/CAC > 5: масштабируй быстрее, недостаточно инвестируешь в growth

У Airbnb, Spotify, Netflix: LTV/CAC > 6-10 для органических каналов.
▶Как интегрировать LTV в рекламные кампании? практика
Google Ads — Value-Based Bidding:
1. Обучаем модель LTV на первые 7 дней после регистрации
2. Передаём predicted_LTV как Conversion Value в Google Ads
3. Smart Bidding (Target ROAS) автоматически платит больше за пользователей с высоким expected LTV

Facebook/Meta — Value Optimization:
Facebook Conversions API: передаём value = predicted LTV при событии Registration/Purchase.
Алгоритм оптимизирует на суммарный Value, не на Count конверсий.

Результат (типично): ROAS вырастает на 20-40% при переходе от CPA (оплата за конверсию) к Value-Based (оплата за LTV).

Важно: нельзя использовать actual LTV — он неизвестен в момент клика. Используем early predicted LTV (7-30 дневные сигналы).
▶Как построить LTV модель для нового продукта без истории? deep
Cold start проблема: нет данных для обучения BG/NBD или ML модели.

Решения (в порядке приоритета):

1. Analogous products: использовать модель похожего продукта того же класса как prior. "Наш SaaS похож на продукт X → берём их LTV-параметры как начальное приближение".
2. Proxy метрики: ранние поведенческие сигналы коррелирующие с LTV: D7 retention, first purchase amount, email engagement. Проверяем на похожих продуктах.
3. Bayesian прайор: начинаем с информативного prior для BG/NBD параметров (из индустрии) → обновляем по мере накопления данных (first 3-6 месяцев).
4. Rapid experimentation: первые 3 когорты × LTV proxy метрики → базовая модель через 3-4 месяца. Обновляем по мере роста данных.
▶Что такое shrinkage в Gamma-Gamma модели? практика
Shrinkage = приближение индивидуальной оценки к популяционному среднему при малом количестве наблюдений.

Формула Gamma-Gamma: $E[M | \bar{m}, x] = \frac{p\gamma + x\bar{m}}{p\gamma + x}$

Пример: популяционное среднее = 1,000₽. Клиент А: 1 покупка на 10,000₽.
E[M|10000, x=1] = (p×γ + 10000)/(p×γ + 1).
При p×γ=2 (аналог "популяционный вес"): E = (2000+10000)/(2+1) = 4,000₽.

Клиент Б: 50 покупок по 10,000₽. E = (2000+500000)/(2+50) ≈ 9,654₽ — почти не сдвинулся.

Смысл: одна дорогая покупка = ненадёжная оценка. 50 дорогих покупок = надёжная. Shrinkage реализует это автоматически.
▶Как CLV связан с churn prediction? популярный
CLV и churn — две стороны одной монеты:

$\text{CLV} = m \cdot \frac{1-\text{churn\_rate}}{1 + d - (1 - \text{churn\_rate})} = m \cdot \frac{r}{1+d-r}$

При churn_rate↑ → retention r↓ → CLV↓.

Практическое использование вместе:
- Churn model: P(уйти в следующие 30 дней)
- CLV model: E[CLV если останется]
- Retention priority score = P(churn) × CLV

Пример: Клиент А: P(churn)=0.8, CLV=200₽ → score=160₽. Клиент Б: P(churn)=0.3, CLV=5000₽ → score=1500₽. Все ресурсы retention → Клиент Б!

Именно так работают retention teams в Spotify, Netflix, SaaS-компаниях.
▶Как оценить параметры BG/NBD? deep
MLE (Maximum Likelihood Estimation): максимизируем log-likelihood по параметрам {r, α, a, b}.

Функция правдоподобия для одного клиента с историей (x, t_x, T):
$L(r,\alpha,a,b|x,t_x,T) = P(\text{X=x}, \text{alive at T}) + P(\text{X=x}, \text{dead at T})$

Каждый компонент — интегралы по гамма и бета-распределениям → аналитически вычислимы через гипергеометрические функции (см. Fader et al. 2005, Appendix A).

На практике:
from lifetimes import BetaGeoFitter
bgf = BetaGeoFitter(penalizer_coef=0.0)
bgf.fit(df['frequency'], df['recency'], df['T'])
print(bgf.summary) # выводит r, α, a, b с SE и p-value

Оптимизация: scipy.optimize.minimize с L-BFGS-B. Сходится за 50-100 итераций для 10k+ клиентов.
▶Как валидировать LTV модель? практика
LTV-валидация сложна: нельзя проверить "реальный LTV" без ожидания.

Стратегии валидации:

1. Backtesting: обучаемся на данных до момента T_train, предсказываем на [T_train, T_train+12m], сравниваем с реальными данными.
2. Cohort validation: сравниваем predicted vs actual LTV для когорт (регистрации за квартал). Aggregate MAPE по когорте.
3. Percentile ranking: предсказанный top-10% CLV должен соответствовать top-10% реальных покупок. Метрика: rank correlation (Spearman ρ).
4. Calibration curve: predicted CLV bucketed vs actual average CLV в каждом бакете. Идеальная модель = диагональ.
5. Business impact: A/B тест retention кампании на predicted top-CLV vs random. Если LTV модель хорошая → кампания на top-CLV даст ROI >> random baseline.
