1. Таксономия утечек с нуля
Шесть механизмов, и ни один не ловится обычной валидацией
📖 Виды утечек
Утечка (data leakage)
Ситуация, когда модель получает при обучении информацию, недоступную в момент реального применения. Метрики валидации завышены, в проде модель проваливается.
Утечка целевой (target leakage)
Признак содержит информацию о целевой, которой в момент прогноза ещё не существует. Пример: «дата закрытия договора» при прогнозе оттока — она появляется после оттока.
Загрязнение train-test (train-test contamination)
Препроцессинг (нормализация, импутация, отбор признаков, target encoding) обучен на всех данных, включая валидационные. Модель косвенно «видела» тест.
Временная утечка
Случайное разбиение временного ряда: модель учится на будущем и предсказывает прошлое. Особенно коварна при агрегатах вида «средний чек клиента за всё время».
Групповая утечка
Один и тот же объект реального мира (клиент, пациент, устройство) присутствует и в обучении, и в валидации. Модель запоминает объект, а не закономерность.
Утечка через дубликаты
Частный случай групповой: полные или почти полные дубликаты строк. Валидация меряет способность запоминать.
🤏 На пальцах: экзамен с ответами на обороте

Утечка — это когда в билете случайно оказались ответы. Студент получает пятёрку и ничего не знает.

Коварство в том, что все обычные проверки проходят. Кросс-валидация даёт отличные цифры — потому что ответы есть в каждом фолде. Отложенная выборка тоже — если утечка встроена в сам признак.

Единственная надёжная проверка — реальность. Модель уезжает в прод, и метрика падает вдвое. К этому моменту на неё уже потрачены месяцы.

Поэтому утечку ищут не метриками, а рассуждением о времени: в какой момент появляется каждое значение каждого признака.

3Почему обычная CV не ловит
Кросс-валидация проверяет ОДНО: «работает ли модель на данных, которых не видела» Она НЕ проверяет: ✗ существует ли признак в момент прогноза ✗ считался ли препроцессинг честно ✗ не встречались ли те же клиенты в другом фолде ✗ идут ли валидационные данные после обучающих во времени Все четыре — про процесс подготовки данных, а не про модель. 4Единственный надёжный вопрос
Для каждого признака спросите: «В какой момент времени это значение становится известным — и будет ли оно известно, когда модель делает прогноз в реальности?» Пример разбора: средний чек за 90 дней → известен на момент прогноза ✓ число обращений всего → включает будущее ✗ дата последнего платежа → зависит от реализации ⚠ тариф → известен ✓ статус договора → меняется при оттоке ✗ Признаки с «всего», «всё время», «последний» почти всегда требуют проверки: они часто считаются по всей истории, включая период после целевого события.

Это упражнение занимает час на пятьдесят признаков и находит больше утечек, чем любые автоматические проверки. Автоматика ловит только следствия — аномально высокую важность, подозрительную форму зависимости. Причину видно только из понимания предметной области.

2. Target encoding: три схемы вручную с нуля
Наивная, leave-one-out и out-of-fold на двенадцати объектах
📖 Термины этой секции
Target encoding (mean encoding, likelihood encoding)
Замена категории на среднее значение целевой в этой категории. Мощный приём для высококардинальных признаков — и самый частый источник утечки.
Наивное кодирование
Среднее по категории считается по всем данным, включая сам объект. Для категории из одного объекта кодировка равна его собственной метке — прямая утечка.
Leave-one-out кодирование
Среднее по категории без текущего объекта. Кажется решением, но создаёт обратную зависимость: внутри категории кодировка отрицательно коррелирует с собственной меткой.
Out-of-fold кодирование
Данные разбиваются на фолды; кодировка для объектов фолда $k$ считается по всем остальным фолдам. Единственная корректная схема.
Fallback для новых категорий
Категория, отсутствующая в остальных фолдах, получает глобальное среднее этих фолдов. Обязательный элемент — без него будут пропуски или, хуже, утечка через подстановку среднего по всем данным.
🤏 На пальцах: почему leave-one-out хуже наивного

Наивная схема очевидно плоха: если категория встретилась один раз, её кодировка равна метке этого объекта. Модель просто читает ответ.

Leave-one-out выглядит как исправление — и оказывается ловушкой. Внутри категории из четырёх объектов с суммой меток 3: объект с меткой 1 получает $(3-1)/3 = 0.667$, объект с меткой 0 получает $(3-0)/3 = 1.000$.

То есть объект с нулевой меткой получил бо́льшую кодировку. Внутри категории связь ровно обратная, корреляция $-1$. Модель выучивает «высокая кодировка → метка 0» — и на тесте, где кодировка считается иначе, знак переворачивается.

3. Сглаживание target encoding средний
Out-of-fold убирает утечку, сглаживание убирает шум
📖 Термины этой секции
Сглаживание (smoothing, shrinkage)
Смешивание среднего по категории с глобальным средним. Редкие категории тянутся к глобальному, частые остаются при своём.
m-оценка (m-estimate)
$e = \frac{n\bar y_{\text{cat}} + m\bar y_{\text{глоб}}}{n + m}$. Параметр $m$ — «сила априорного», выраженная в числе воображаемых наблюдений.
Вес свидетельства категории
$\frac{n}{n+m}$ — какая доля кодировки берётся из самой категории. При $n = m$ ровно половина.
Эмпирический байес для $m$
$m = \frac{\bar y(1-\bar y)}{s^2} - 1$, где $s^2$ — дисперсия средних по категориям. Тот же расчёт, что при подборе силы априорного в теме 6.3.
Шум CatBoost (ordered target statistics)
Альтернатива фолдам: случайная перестановка объектов и кодировка только по предшествующим. Разбор — в теме 1.1.
🤏 На пальцах: одно наблюдение ничего не говорит

Категория встретилась один раз, метка была 1. Значит ли это, что вероятность в этой категории равна 100%?

Очевидно нет. Одно наблюдение — это почти никакая информация. Разумная оценка должна быть близка к глобальному среднему.

Категория встретилась тысячу раз, доля единиц 0.80. Здесь глобальное среднее уже не важно — данных достаточно.

Сглаживание задаёт плавный переход между этими крайностями через один параметр $m$: сколько наблюдений нужно, чтобы категория «заслужила» половину веса.

📐 m-оценка
$$e_{\text{cat}} = \frac{n_{\text{cat}}\,\bar y_{\text{cat}} \;+\; m\,\bar y_{\text{глоб}}}{n_{\text{cat}} + m} = \underbrace{\frac{n}{n+m}}_{\text{вес категории}}\bar y_{\text{cat}} \;+\; \underbrace{\frac{m}{n+m}}_{\text{вес глобального}}\bar y_{\text{глоб}}$$

Байесовская интерпретация: $m$ — число наблюдений в априорном распределении. Формула эквивалентна апостериорному среднему Beta-Bernoulli с $\alpha_0 = m\bar y_{\text{глоб}}$ и $\beta_0 = m(1-\bar y_{\text{глоб}})$ — то же, что в теме 6.3 при холодном старте.

2Подбор m через эмпирический байес
Идея Если между категориями есть реальные различия, дисперсия их средних будет больше, чем объясняется одним биномиальным шумом. Избыток и даёт оценку m. Расчёт ȳ = 0.583333 — глобальное среднее s² — наблюдаемая дисперсия средних по категориям (по категориям с достаточным n) m = ȳ(1 − ȳ)/s² − 1 Пример: ȳ = 0.12, s² = 0.0088 m = 0.12 × 0.88 / 0.0088 − 1 = 0.1056 / 0.0088 − 1 = 12.0 − 1 = 11.0 Пример: категории различаются слабо, s² = 0.0021 m = 0.1056 / 0.0021 − 1 = 50.29 − 1 = 49.3 слабые различия → сильное сглаживание Пример: категории различаются сильно, s² = 0.0352 m = 0.1056 / 0.0352 − 1 = 3.0 − 1 = 2.0 сильные различия → почти без сглаживания

Формула интерпретируется напрямую: чем сильнее категории реально различаются, тем меньше нужно сглаживать. При $s^2 \to \bar y(1-\bar y)$ (различия максимальны) $m \to 0$; при $s^2 \to 0$ (различий нет) $m \to \infty$ и все категории схлопываются в глобальное среднее.

Ровно тот же расчёт — в теме 6.3 при подборе силы контентного априорного для холодного старта. Там $\kappa = m(1-m)/s^2 - 1$; здесь $m$ вместо $\kappa$, но математика идентична: это оценка концентрации бета-распределения по методу моментов.

4. Утечка через препроцессинг средний
Самая распространённая и самая незаметная
📖 Термины этой секции
fit на всех данных
Обучение преобразователя (scaler, imputer, encoder, selector) на объединении обучающей и валидационной выборок. Валидационные данные влияют на преобразование — они «просочились».
Pipeline
Конструкция, связывающая препроцессинг и модель в один объект. При кросс-валидации весь pipeline переобучается внутри каждого фолда — единственный надёжный способ не ошибиться.
Статистики, зависящие от данных
Среднее, стандартное отклонение, медиана, квантили, границы бинов, словарь категорий, компоненты PCA, параметры Box-Cox. Все они должны считаться только по обучающей части.
Безопасные преобразования
Не зависящие от данных: логарифм, извлечение дня недели из даты, арифметика между признаками одной строки. Их можно применять до разбиения.

2Почему StandardScaler всё же опасен
Завышение всего 0.0013 — казалось бы, можно игнорировать. Но: вы сравниваете модель A (AUC 0.8468) с моделью B (AUC 0.8455) и выбираете A. Разница 0.0013 — ровно порядка завышения от утечки. То есть решения о выборе модели принимаются на уровне шума, создаваемого утечкой. Плюс эффект накапливается: scaler + imputer + дискретизация = 0.0083 при типичной разнице между кандидатами 0.005–0.015 это уже определяющая величина. 3Правильная схема
Неправильно ① fit_transform препроцессинга на ВСЕХ данных → ② cross_val_score
Правильно ① Pipeline(препроцессинг, модель) → ② cross_val_score(pipeline)
Что делает Pipeline внутри каждого фолда для каждого фолда k: ① scaler.fit(X_train_k) только обучающая часть ② X_train_k = scaler.transform(X_train_k) ③ X_val_k = scaler.transform(X_val_k) параметрами из ① ④ model.fit(X_train_k, y_train_k) ⑤ score на X_val_k Пять фолдов → пять независимых scaler'ов. Валидационная часть никогда не участвует в fit.
Что нельзя завернуть в Pipeline ① Разбиение на train/test — делается ДО всего ② Удаление дубликатов — тоже до, но осторожно: удаление дубликатов после разбиения может оставить копии в разных частях ③ Ресемплинг (SMOTE) — нужен imblearn.Pipeline, обычный sklearn.Pipeline применит SMOTE и к валидации тоже ④ Target encoding — нужна реализация, поддерживающая fit/transform раздельно (category_encoders, а не ручной groupby)

Правило без исключений: любой шаг, у которого есть fit, должен быть внутри Pipeline. Если шаг написан вручную через groupby или np.mean — он почти наверняка течёт.

Когда случайное разбиение — уже ошибка
📖 Термины этой секции
Временная утечка
Обучение на данных, идущих после валидационных по времени. Модель знает будущее. Возникает при случайном разбиении любых данных с временной структурой.
TimeSeriesSplit
Схема, где валидация всегда позже обучения. Обучающая часть растёт от фолда к фолду или скользит окном.

Промежуток между концом обучения и началом валидации. Нужен, когда целевая определена на горизонте: при прогнозе оттока за 30 дней зазор должен быть не меньше 30 дней.

Один объект реального мира в обучении и валидации одновременно. Модель запоминает объект. Особенно опасно при повторяющихся записях на клиента.
GroupKFold
Разбиение, гарантирующее, что все записи одной группы попадают в один фолд.

6. Permutation importance средний
Механизм и три ловушки, одна из которых хуже, чем у SHAP
📖 Термины этой секции
Permutation importance
Перемешать значения признака между объектами и замерить падение качества. Падение и есть важность: если модель зависела от признака, разрушение связи её ломает.
Число повторов
Перемешивание случайно, поэтому его повторяют $R$ раз и усредняют. При $R=1$ оценка настолько шумна, что порядок признаков меняется от запуска к запуску.
Отрицательная важность
Качество после перемешивания выросло. Означает, что признак вредил — обычно из-за переобучения на нём. Кандидат на удаление.
Внемножественные точки
Перемешивание создаёт невозможные комбинации признаков — та же проблема, что у interventional SHAP (тема 1.4, секция 5).
Зануление при дублировании
Главное отличие от SHAP. При двух копиях признака перемешивание одной не вредит: модель берёт вторую. Обе получают нулевую важность, и суммарная важность исчезает, а не делится.

Это принципиальное различие двух методов. У SHAP сумма по группе сохраняется — важность делится (тема 1.4, секция 11). У permutation она пропадает: обе копии страхуют друг друга, и ни одна не выглядит нужной.

Практическое следствие. Permutation importance нельзя использовать для отбора признаков при наличии коррелированных групп — он выбросит всю группу целиком. Лекарство: групповое перемешивание — перемешивать всю коррелированную группу одновременно. Тогда важность группы возвращается к 0.0409.

7. Boruta продвинутый
Отбор со статистическим тестом вместо произвольного порога
📖 Термины этой секции
Boruta
Метод отбора «всех релевантных» признаков. Создаёт теневые копии, сравнивает с ними реальные признаки и применяет биномиальный тест.
Теневой признак (shadow feature)
Случайно перемешанная копия реального признака. По построению не содержит связи с целевой — эталон «шума с тем же распределением».
Попадание (hit)
Реальный признак получил важность выше, чем максимальная среди всех теневых, в данной итерации.
Биномиальный тест
При нулевой гипотезе «признак — шум» вероятность попадания равна 0.5. Число попаданий за $N$ итераций сравнивается с $\text{Binom}(N, 0.5)$.
Все релевантные против минимально достаточных
Ключевое отличие Boruta. Он ищет все признаки, связанные с целевой, включая избыточные. Большинство методов ищут минимальный достаточный набор. Это разные задачи.
🤏 На пальцах: эталон шума

Проблема любого отбора: где порог? Важность 0.03 — это много или мало? Ответ зависит от задачи, и произвольный порог даёт произвольный результат.

Идея Boruta: создать признак, про который точно известно, что он шум — перемешанную копию реального. Тогда «важнее шума» становится проверяемым утверждением, а не вопросом вкуса.

Берётся максимум среди всех теневых, а не среднее: это автоматически даёт поправку на множественные сравнения, потому что случайно превысить максимум из пятнадцати гораздо труднее, чем среднее.

9. Высококардинальные категории продвинутый
Где утечка и переобучение особенно тесно переплетены
📖 Способы кодирования
One-hot
Отдельный бинарный столбец на категорию. При 100 000 значений — неприменимо: матрица разреженная, память и время растут линейно.
Ordinal / label encoding
Замена на произвольное целое. Для деревьев работает, но порядок случаен: дерево вынуждено дробить диапазон на много разбиений.
Frequency encoding
Замена на частоту категории. Не использует целевую — утечка невозможна. Работает удивительно часто, потому что редкость сама по себе информативна.
Target encoding
Разбор в секциях 2–3. Мощнее всех, опаснее всех.
Hashing trick
Хеш категории по модулю $K$. Фиксированная размерность, коллизии смешивают несвязанные категории. Утечки нет.
Обучаемые эмбеддинги
Вектор на категорию, обучаемый вместе с моделью. Для табличного DL и для CatBoost косвенно. Требует много данных на категорию.

10. Отбор признаков внутри кросс-валидации продвинутый
CV AUC 0.81 на чистом шуме — самая известная катастрофа в отборе
📖 Термины этой секции
Смещение отбора (selection bias)
Если признаки отобраны с использованием целевой на всех данных, любая последующая валидация оптимистично смещена — валидационные объекты уже повлияли на то, какие признаки видит модель.
Вложенная кросс-валидация (nested CV)
Два уровня: внешний оценивает качество, внутренний отбирает признаки и подбирает гиперпараметры. Внутренний работает только на обучающей части внешнего фолда.
Множественное тестирование
При 10 000 случайных признаков и 1 000 объектов максимальная выборочная корреляция достигает 0.12 чисто случайно. Отбор двадцати лучших даёт двадцать «сильных» признаков из чистого шума.
Стабильность отбора
Доля признаков, попадающих в отобранный набор во всех фолдах. Низкая стабильность означает, что отбор ловит шум.
🤏 На пальцах: двадцать лучших из десяти тысяч случайных

Возьмём 1 000 объектов и 10 000 признаков, заполненных случайными числами. Целевая тоже случайна. Связи нет никакой.

Но выборочная корреляция каждого признака с целевой — случайная величина со стандартным отклонением $1/\sqrt{1000} \approx 0.032$. Максимум из десяти тысяч таких величин будет около $3.9\sigma \approx 0.12$.

Отберём двадцать признаков с наибольшей корреляцией. Все они имеют $|r| \approx 0.11$–$0.12$ — выглядят как сильный сигнал.

Теперь кросс-валидируем модель на этих двадцати признаках. И получаем AUC 0.81 — на данных, где нет вообще ничего. Потому что отбор использовал целевую всех объектов, включая те, что попадут в валидационные фолды.

11. Жадные схемы отбора средний
RFE, forward, backward и почему пошаговое удаление опасно
📖 Термины этой секции
Backward elimination
Начать со всех признаков, на каждом шаге удалять наименее полезный. Дорого, но учитывает взаимодействия.
Forward selection
Начать с пустого набора, добавлять наиболее полезный. Дешевле, но может не найти признаки, полезные только в паре.
RFE (Recursive Feature Elimination)
Backward, но удаляется сразу группа признаков по важности модели, а не по одному. Компромисс между качеством и стоимостью.
Ловушка пошагового удаления
Каждый шаг безопасен по отдельности, потому что коррелированные признаки страхуют друг друга; обвал происходит на последнем из группы. Подробно — в теме 1.4, секция 11.

13. Подводные камни продвинутый
Пятнадцать ошибок
1Использовать leave-one-out target encoding. Формула $e_i = (\Sigma - y_i)/(n-1)$ даёт внутри категории корреляцию ровно $-1$ с собственной меткой. На нашем примере общая корреляция $-0.439$, test AUC на большой выборке 0.508 — хуже случайного угадывания.
2Считать, что сглаживание решает проблему утечки. Разрыв train–test упал с 0.382 до 0.243 — всё ещё катастрофа. Сглаживание лечит шум редких категорий, out-of-fold лечит утечку. Нужны оба.
3Отбирать признаки на всех данных перед CV. На чистом шуме из 10 000 признаков CV даёт AUC 0.810. Правильная вложенная схема даёт 0.501. Завышение растёт с числом признаков — ровно наоборот здравому смыслу.
4Отбирать внутри фолда, но тюнить гиперпараметры снаружи. Полумера снижает завышение с 0.310 до 0.078, не убирая его. Утечка возвращается через выбор гиперпараметров.
5Не заворачивать препроцессинг в Pipeline. Правило: любой шаг с методом fit должен быть внутри. Шаг, написанный вручную через groupby или np.mean, почти наверняка течёт.
6Применять SMOTE до разбиения. Синтетический объект в обучении может быть интерполяцией объекта, попавшего в валидацию — фактически его копия. Завышение 0.109. Нужен imblearn.Pipeline, а не обычный.
7Игнорировать «безобидную» утечку через scaler. Завышение 0.0013 при N = 50 000, но 0.0384 при N = 500. И на большой выборке оно того же порядка, что разница между сравниваемыми моделями — то есть выбор модели делается на уровне шума от утечки.
8Случайно разбивать данные с временной структурой. Прогноз оттока: KFold 0.892, TimeSeriesSplit 0.734, прод 0.729. TimeSeriesSplit предсказал реальность с точностью 0.005, KFold ошибся на 0.158.
9Забыть зазор при TimeSeriesSplit. Если целевая определена на горизонте 30 дней, зазор должен быть не меньше 30 дней. Без него завышение 0.027 даже при правильном по времени разбиении.
10Не группировать по сущности. При пяти записях на клиента вероятность, что клиент есть и в обучении, и в валидации, равна 99.97%. KFold растёт с 0.751 до 0.961 с числом записей — это измерение памяти, а не обобщения.
11Группировать не на том уровне. Медицинские снимки: KFold 0.943, по пациенту 0.812, по больнице 0.734, прод в новой больнице 0.729. Группировка по пациенту всё ещё завышает на 0.078 из-за артефактов оборудования.
12Отбирать признаки по permutation importance при коррелированных группах. Две копии признака дают важности 0.0009 и 0.0011 против 0.0412 у одиночного — 95% важности исчезает. SHAP хотя бы делит; permutation уничтожает. Лекарство — групповое перемешивание.
13Удалять признаки по одному до обвала. Шесть коррелированных копий: пять удалений дают суммарно $-0.004$, шестое $-0.045$. Пошаговая проверка смотрит на шаг вперёд и не видит, что уходит вся группа. Кластеризуйте признаки перед отбором.
14Отбирать по корреляции с целевой. В синтетике с известным ответом корреляция нашла 0 из 4 взаимодействующих признаков — они по отдельности с целевой не связаны. Потеря 0.052 AUC против SHAP.
15Применять target encoding к признаку, где почти все категории уникальны. При 96% строк в категориях меньше 20 наблюдений вклад составил +0.0009 AUC при полном риске утечки. Проверьте долю мелких категорий до, а не после.

Автоматическая проверка перед каждым выкатом

Мотив. За полтора года три модели ушли в прод с утечками, каждая обнаружена через 4–8 недель после выката. Суммарные потери — не столько деньги, сколько доверие к команде.

Гейт из четырёх автоматических тестов. Первый — перемешивание целевой: весь пайплайн прогоняется на случайных метках, метрика должна лежать в $0.5 \pm 3\sigma$. Второй — разрыв train–test выше 0.15 блокирует выкат. Третий — доля топ-1 признака в суммарном SHAP выше 0.55 требует ручного подтверждения. Четвёртый — сравнение AUC при KFold и при GroupKFold: расхождение выше 0.05 блокирует.

Первый прогон нашёл две утечки в уже работавших моделях. В одной target encoding считался вне Pipeline — тест с перемешанной целевой дал 0.688 вместо 0.50. Во второй забыли GroupKFold на данных с несколькими заявками от одного клиента.

Стоимость гейта — 11 минут на прогон, из них 9 занимает перемешивание целевой (полное переобучение). Это оказалось приемлемой ценой за то, чтобы класс ошибок закрылся окончательно.

Ложные срабатывания были. Антифрод-модель законно имеет AUC 0.96 и топ-1 признак с долей 0.58. Для неё пороги вынесены в конфигурацию модели с обязательным комментарием, почему они изменены — так исключение остаётся видимым при ревью.

🧬
Геномика: 40 000 признаков, 900 пациентов
Классический режим, где отбор без вложенной CV бессмысленен

Постановка. Экспрессия 40 000 генов, 900 пациентов, бинарный исход. Отношение объектов к признакам — 0.0225.

Первая версия исследования сообщала AUC 0.89. Схема: отобрать 50 генов с наибольшей разницей между группами, затем 10-кратная CV. Классическая ошибка из секции 10.

Пересчёт с вложенной CV дал 0.61. Отбор внутри каждого фолда, пересечение наборов между фолдами — 4 гена из 50. Низкое пересечение само по себе означало, что отбор ловит шум.

Что осталось после честной оценки. Четыре гена, попавшие во все десять фолдов, дали AUC 0.61 — скромно, но воспроизводимо. Это и был реальный результат. Публикация с 0.89 не воспроизвелась бы на независимой когорте и стоила бы репутации.

Отдельная проблема — партии обработки образцов. Образцы обрабатывались партиями по 90 штук, и партия коррелировала с исходом (больных набирали позже). GroupKFold по партии снизил AUC ещё до 0.57. Финальная оценка — по независимой когорте из другого центра: 0.58.

🏪
Target encoding для 60 000 товаров
Где OOF и сглаживание дают реальный прирост

Задача. Прогноз вероятности возврата товара. Признак «артикул» с 60 000 значений, 2.1 млн строк, в среднем 35 строк на артикул.

Диагностика до внедрения. Доля строк в категориях меньше 20 наблюдений — 31%. По правилу из секции 9 это зона «нужно сглаживание с $m \ge 20$». Доля новых артикулов на тесте — 6.4%, fallback сработает редко. Признак стоит риска.

Схема. OOF с $K=5$, разбиение по времени, а не случайное: возвраты сезонны, и случайные фолды дали бы временную утечку поверх всего остального. Сглаживание $m = 24$, подобрано эмпирическим байесом ($\bar y = 0.083$, $s^2 = 0.00304$).

Результат. Test AUC 0.7812 против 0.7614 без признака — прирост 0.0198, крупнейший из всех фич за квартал. Наивная версия давала train AUC 0.94 и test 0.71, то есть ухудшала модель на 0.05 при выдающихся цифрах на обучении.

В проде — отдельная тонкость. Кодировка для инференса считается по всей обучающей выборке, а не по фолдам: фолды нужны только при обучении. Это два разных артефакта, и путаница между ними — источник расхождения между офлайн и онлайн метриками. Таблица кодировок версионируется вместе с моделью.

⏱️
Feature store и утечка через агрегаты
Самая трудноуловимая форма временной утечки

Проблема. Признак «средний чек клиента» считался в витрине как среднее по всем транзакциям. При обучении на исторических данных это среднее включало транзакции, произошедшие после момента, на который делался прогноз.

Почему это не заметили полгода. Разрыв train–test был нормальным — 0.014. Утечка одинаково присутствовала в обучении и валидации. Тест с перемешанной целевой тоже проходил: агрегат не использует целевую. Ни один автоматический тест не срабатывал.

Нашли тестом 6 — сравнением схем валидации. TimeSeriesSplit дал AUC 0.771 против 0.864 у KFold. Расхождение 0.093 при том, что временной структуры в модели формально не было, указало прямо на агрегаты.

Решение — point-in-time корректность. Витрина перестроена так, что каждый агрегат считается с явным ограничением по времени: AS OF timestamp. Для обучающего объекта с датой 15 марта средний чек считается только по транзакциям до 15 марта. Это дороже в вычислении примерно вдвое и является обязательным требованием к любому feature store.

Проверка после исправления. KFold 0.774, TimeSeriesSplit 0.771 — расхождение 0.003. Прод показал 0.769. Модель стала «хуже» на 0.09 AUC на бумаге и не изменилась в реальности: раньше цифра просто была неправдой.

Сокращение признаков ради латентности
Где отбор нужен не для качества, а для инфраструктуры

Постановка. 340 признаков, из них 190 требуют онлайн-запросов к четырём разным сервисам. p99 сбора признаков — 140 мс при бюджете 60 мс.

Отбор оптимизирует не качество, а стоимость. Каждому признаку приписана цена в миллисекундах и в рублях за запрос. Задача: минимизировать суммарную цену при падении AUC не более 0.005.

Метод — SHAP (interventional) с кластеризацией. Сначала признаки кластеризованы по корреляции $|r| > 0.85$ — получилось 214 кластеров из 340 признаков. Внутри кластера оставлен самый дешёвый представитель, а не самый важный. Это дало сокращение до 214 признаков с потерей 0.0011 AUC.

Дальше — жадное удаление по отношению «важность / стоимость». Не по важности: признак с важностью 0.02 и ценой 40 мс хуже признака с важностью 0.01 и ценой 2 мс. Удаление по этому отношению довело набор до 96 признаков при потере 0.0043.

Итог. p99 сбора 38 мс вместо 140, три из четырёх сервисов перестали вызываться синхронно. AUC 0.8412 → 0.8369. Ключевое решение — оставлять в кластере дешёвого, а не важного: внутри кластера корреляция 0.85+, и разница в важности между представителями меньше шума отбора.

15. Вопросы и ответы
Тридцать вопросов

Утечки: основы

1. Что такое утечка одним предложением?
Модель при обучении получает информацию, недоступную в момент реального применения. Метрики валидации завышены, в проде модель проваливается.
2. Почему кросс-валидация не ловит утечку?
CV проверяет одно — работает ли модель на невиданных данных. Она слепа к тому, существует ли признак в момент прогноза, честно ли считался препроцессинг и не встречались ли те же клиенты в других фолдах. Утечка присутствует во всех фолдах одинаково.
3. Какой самый надёжный способ найти утечку?
Ручной разбор признаков по времени: «в какой момент это значение становится известным, и будет ли оно известно при реальном прогнозе?» Час на пятьдесят признаков, находит больше, чем любая автоматика.
4. Первый признак того, что что-то не так?
Качество существенно выше реалистичного потолка задачи. AUC 0.974 в прогнозе оттока физически невозможен — если бы отток был так предсказуем, его бы предотвращали.

Target encoding

5. Чем плоха наивная схема?
Для категории из одного объекта кодировка равна его собственной метке. В реальных данных с тысячами категорий половина встречается 1–2 раза, то есть половина строк получает ответ в явном виде.
6. Почему leave-one-out хуже наивной?
Формула $e_i = (\Sigma - y_i)/(n-1)$ линейно убывает по $y_i$, значит внутри категории корреляция ровно $-1$. Модель учит перевёрнутую зависимость; на тесте знак переворачивается. Test AUC 0.508 против 0.612 у наивной.
7. Как устроено out-of-fold кодирование?
Данные разбиваются на $K$ фолдов; кодировка для объектов фолда $k$ считается по остальным фолдам. Категория, отсутствующая в остальных, получает глобальное среднее тех же фолдов — fallback обязателен.
8. Заменяет ли сглаживание out-of-fold?
Нет. Наивная схема со сглаживанием $m=10$ даёт разрыв train–test 0.243 вместо 0.382 — всё ещё катастрофа. Это два лекарства от разных болезней: OOF от утечки, сглаживание от шума редких категорий.
9. Как подобрать параметр сглаживания $m$?
Эмпирический байес: $m = \bar y(1-\bar y)/s^2 - 1$, где $s^2$ — дисперсия средних по категориям. В замере формула дала $m=11$ при оптимуме перебором около 10. Тот же расчёт, что при подборе априорного в теме 6.3.
10. Как понять, стоит ли target encoding риска?
Доля строк в категориях меньше 20 наблюдений. Меньше 10% — безопасно; 10–40% — нужно сглаживание; больше 70% — не использовать. При 96% мелких категорий вклад составил $+0.0009$ AUC при полном риске.

Препроцессинг и разбиение

11. Какой препроцессинг опаснее всего?
Всё, что использует целевую: отбор признаков (завышение 0.307), target encoding (0.291), SMOTE до разбиения (0.109). Всё, что использует только $X$ — scaler, imputer, PCA — завышает на 0.001–0.01.
12. Почему SMOTE до разбиения — критическая ошибка?
Синтетический объект строится интерполяцией реальных. Если он создан из объекта, попавшего в валидацию, это фактически его копия в обучающей выборке. Нужен imblearn.Pipeline: обычный sklearn.Pipeline применит SMOTE и к валидации.
13. Если утечка через scaler даёт всего 0.0013, стоит ли беспокоиться?
Да. Это того же порядка, что разница между сравниваемыми моделями — то есть решения принимаются на уровне шума от утечки. Плюс эффект накапливается по шагам и растёт до 0.0384 при $N=500$.
14. Как правильно организовать препроцессинг?
Всё, у чего есть fit, — внутри Pipeline. Тогда при CV каждый фолд получает свой независимый препроцессор, обученный только на обучающей части. Шаг, написанный вручную через groupby, почти наверняка течёт.
15. Когда нужен TimeSeriesSplit?
Всегда, когда у данных есть временная структура. Замер: KFold 0.892, TimeSeriesSplit 0.734, прод 0.729 — вторая схема предсказала реальность с точностью 0.005.
16. Зачем зазор между обучением и валидацией?
Если целевая определена на горизонте (например, «уйдёт за 30 дней»), метка обучающего объекта считается по периоду, пересекающемуся с валидационным. Зазор должен быть не меньше горизонта; без него завышение 0.027.
17. Насколько опасна групповая утечка?
При пяти записях на клиента вероятность, что клиент есть и в обучении, и в валидации — 99.97%. AUC KFold растёт с 0.751 до 0.961 с числом записей, тогда как GroupKFold стабильно даёт 0.751–0.753.
18. По какому уровню группировать, если групп несколько?
По самому крупному, на котором возможна утечка. Медицинские снимки: по пациенту 0.812, по больнице 0.734, прод в новой больнице 0.729. Вопрос: на каких данных модель будет работать в проде?

Методы отбора

19. Чем permutation importance принципиально отличается от SHAP?
Поведением при дублировании. SHAP делит важность (сумма по группе сохраняется: 0.400). Permutation её уничтожает: две копии дают 0.0009 и 0.0011 против 0.0412 у одиночного признака — исчезает 95%.
20. Как понять, значима ли permutation importance?
Сравнить со стандартным отклонением по повторам. Доход: $0.1278/0.0041 = 31.2\sigma$ — значим. Возраст: $0.0014/0.0022 = 0.6\sigma$ — неотличим от нуля. Отрицательная важность означает, что признак вредил.
21. Permutation на трейне или на отложенной?
Обе полезны. На отложенной — «нужен ли признак для обобщения». На трейне — «насколько модель на него опирается». Их отношение — прямая мера переобучения: у ID клиента оно 298×, у дохода 1.05×.
22. Как устроена Boruta?
Создаёт перемешанные копии всех признаков, обучает модель на реальных + теневых, засчитывает «попадание», если реальный признак важнее максимума теневых. Число попаданий за $N$ итераций проверяется биномиальным тестом с $p=0.5$.
23. Почему берётся максимум теневых, а не среднее?
Максимум даёт автоматическую поправку на множественные сравнения: случайно превысить максимум из пятнадцати гораздо труднее, чем среднее.
24. Что означают три исхода Boruta?
Подтверждён — статистически лучше шума; отвергнут — хуже шума; не решено — данных не хватило. При 20 итерациях и Бонферрони на 15 признаков подтверждают 17 попаданий, отвергают 3 — с одинаковым $p = 0.00129$ по симметрии биномиального распределения.
25. Какой метод отбора выбрать?
SHAP interventional с проверкой удалением: в синтетике с известным ответом он единственный нашёл ровно нужное (8 информативных + 4 взаимодействия, ноль мусора) за 4 секунды. Boruta — когда нужны все релевантные признаки, а не минимальный набор.
26. Почему отбор по корреляции плох?
Он меряет парную связь и пропускает взаимодействия — признаки, полезные только вместе, по отдельности с целевой не связаны. В замере: 0 из 4 взаимодействий, потеря 0.052 AUC.

Валидация отбора

27. Что даёт отбор признаков на всех данных перед CV?
На чистом шуме из 10 000 признаков — CV AUC 0.810. Правильная вложенная схема даёт 0.501. Причина: признак попал в топ за то, что случайно совпал с метками валидационных объектов.
28. Как быстро проверить, есть ли вообще что отбирать?
Отобрать признаки отдельно в каждом фолде и посчитать пересечение наборов. Чистый шум: 0 признаков во всех фолдах. Реальный сигнал: 16 из 20. Если пересечение меньше половины — отбор ловит шум.
29. Какой тест на утечку самый мощный?
Перемешать целевую и прогнать весь пайплайн. Правильный даёт $\approx 0.50$; отбор вне Pipeline — 0.810, target encoding вне Pipeline — 0.688, SMOTE до разбиения — 0.751. Тридцать строк кода в CI закрывают целый класс ошибок.
30. Что этот тест не ловит?
Групповые и временные утечки — при перемешанной целевой групп и времени фактически нет. Для них нужен тест 6: прогнать одну модель KFold, GroupKFold и TimeSeriesSplit и сравнить. Расхождение выше 0.05 указывает на соответствующий тип утечки.
