# Applied ML Course → веб-приложение: передача проекта

Документ для старта новой сессии в Claude Code (VS Code). Описывает, что уже сделано, где лежат файлы, по каким правилам пишется контент, как он собирается, что должно получиться в приложении и с чего начинать.

## 1. Что это за проект

**Учебный курс по прикладному машинному обучению на русском языке** — около 75 тем в 10 блоках, каждая тема — самостоятельная HTML-страница с теорией, формулами, пошаговыми расчётами, интерактивными графиками, подводными камнями, задачами и вопросами с собеседований. К блокам есть тесты.

Цель владельца — глубоко изучить ML (от основ вероятности до LLM) и подготовиться к собеседованиям. Отсюда требования: материал должен **запоминаться**, должен быть **персональный прогресс** (что прочитано, что нет), **тесты и повторение**.

**Текущее состояние:** всё — набор HTML-файлов в одной папке. **Задача:** превратить это в нормальное кроссплатформенное веб-приложение (PWA) с каталогом, чтением, тестами, интервальным повторением и синхронизацией прогресса через Firebase. Приложение **отдельное**, с Life OS владельца не связывается (код Life OS можно посмотреть как образец стека и стиля).

## 5. Как собирается тема нового стандарта

### Исходник

`_src/<file>.src.html` — обычный HTML, в котором формулы записаны LaTeX-ом в специальных тегах:

- `<tex>…</tex>` — формула в строке;
- `<texd>…</texd>` — формула отдельным блоком;
- `<!--KATEX_CSS-->` — место для CSS KaTeX со шрифтами (base64);
- `<!--CHARTJS-->` — место для встроенного Chart.js.

Макросы KaTeX (заданы в `build.js`): `\E` → 𝔼, `\Var`, `\Cov`, `\P` → P.

### Сборка

```bash
node _tools/build.js _src/block0_03_bayes.src.html
# → block0_03_bayes.html рядом с _src (в корне папки)
```

Сборщик рендерит все формулы через `katex.renderToString`, падает с кодом 2 при ошибке TeX и печатает число формул.

## 7. Что должно получиться: приложение

### Принципы

- **Отдельное веб-приложение (PWA)**: работает в браузере на компьютере и телефоне, ставится на домашний экран, читается офлайн.
- **Firebase** (у владельца уже есть аккаунт и опыт): Authentication (вход через Google), Firestore (прогресс), Hosting (публикация). Тариф Spark (бесплатный) — с запасом для одного пользователя. Можно создать отдельный Firebase-проект для курса.
- **Тёмная тема** в стиле страниц блока 0.
- Контент — статические файлы; приложение — оболочка вокруг них.

### Рекомендуемый стек (уточнить после просмотра кода Life OS)

- Vite + React + TypeScript, React Router;
- Firebase JS SDK v10+ (modular): `auth`, `firestore` с офлайн-кэшем (`persistentLocalCache`);
- `vite-plugin-pwa` (service worker, кэш контента);
- стили — CSS-переменные из `COURSE_STANDARD` (или Tailwind, если так сделан Life OS);
- контент-пайплайн — Node-скрипты (развитие `_tools/build.js`).

### Функции

**1. Каталог.** Блоки → (модули для блока 0) → темы. У темы: номер, название, статус контента (new / mid / old), статус пользователя (не начата / читаю N% / прочитана / тест пройден), время чтения. Кнопка «Продолжить» — последняя открытая тема и секция.

**2. Чтение.** Тема открывается внутри приложения (в первой версии — `iframe` на статический HTML). Внутри страницы — небольшой скрипт-мост (`postMessage`) сообщает оболочке:

- какая секция видна (по `IntersectionObserver` на `section[id^=s]`) → отметка «секция прочитана», если она пробыла в зоне видимости достаточно долго;
- открытия `details.qa` и задач (интерес / самопроверка);
- (позже) ответы во встроенных «угадай» и мини-проверках.

Плюс ручные отметки на теме: «понял», «вернуться позже», заметка.

**3. Тесты.**

- по теме, по блоку, перемешанный по выбранным блокам, «экзамен» (N случайных вопросов на время);
- режим «собеседование» (устный): вопрос → вспоминаю → «показать ответ» → самооценка «знал / частично / не знал»;
- после ответа — объяснение, ссылка на секцию темы;
- история попыток, лучший результат, слабые темы.

**4. Интервальное повторение.** Карточки из Q&A тем и вопросов тестов. Ежедневная очередь «пора повторить», алгоритм SM-2 или упрощённые интервалы 1 → 3 → 7 → 21 → 60 дней с поправкой на самооценку. Карточка попадает в колоду, когда тема прочитана (или по кнопке «добавить в повторение»).

**5. Статистика.** Прочитано по блокам, серия дней, карточек «созрело / выучено», точность по темам, «слабые места» (темы с частыми «не знал»).

**6. (Позже)** поиск по курсу, закладки, глоссарий, карта связей между темами, страница «Задачи на Python».

### Модель данных

**Контент (статические JSON, генерируются из файлов курса):**

```ts
// content/manifest.json
type Manifest = {
  version: string;
  blocks: { id: string; title: string; subtitle: string; color: string;
            modules?: { id: string; title: string; topicIds: string[] }[];
            topicIds: string[] }[];
  topics: { id: string;            // "0.3", "1.15"
            slug: string;          // "block0_03_bayes"
            blockId: string; title: string; summary: string;
            contentStatus: 'new'|'mid'|'old';
            sections: { id: string; title: string }[];   // s1..s15 из .snav
            readingMinutes: number;
            file: string }[];      // путь к HTML
};

// content/questions.json — единый банк вопросов
type Question = {
  id: string;                      // стабильный, например "b9-q017" или "t0.3-qa-12"
  topicId: string; blockId: string;
  kind: 'mcq' | 'open';            // тест с вариантами или вопрос с открытым ответом (Q&A)
  level?: 'junior'|'middle'|'senior';
  q: string; options?: string[]; correct?: number;
  answer?: string;                 // для open
  explanation?: string;
  sectionRef?: string;             // "s8" — куда вести при ошибке
  source: string;                  // откуда извлечён (файл)
};
```

**Прогресс пользователя (Firestore):**

```
users/{uid}
  profile: { createdAt, lastActiveAt, streak, settings }
users/{uid}/topics/{topicId}
  { status, sectionsRead: string[], lastSection, readPct, startedAt, completedAt,
    marks: { understood?: bool, revisit?: bool }, note? }
users/{uid}/cards/{questionId}
  { due: Timestamp, interval: number, ease: number, reps: number, lapses: number,
    lastGrade: 0|1|2|3, history: [{t, grade}] (последние N) }
users/{uid}/attempts/{attemptId}
  { mode, scope, startedAt, finishedAt, answers: [{qid, chosen, correct, ms}], score }
```

Правила безопасности: каждый пользователь читает и пишет только `users/{request.auth.uid}/**`.

### Как подготовить контент для приложения (контент-пайплайн)

1. **Сборщик в «режиме приложения»** для страниц из `_src`: не встраивать KaTeX CSS / шрифты и Chart.js в каждый файл, а подключать общие `/assets/katex/katex.min.css` и `/assets/chart.umd.js`. Страница станет ~150 КБ вместо 1.4 МБ. Оставить и «самостоятельный» режим (как сейчас) для офлайн-просмотра без приложения.
2. **Старые страницы блоков 1–9**: заменить CDN-ссылку на Chart.js локальной `/assets/chart.umd.js`, добавить `Chart.defaults.animation = false` (иначе в некоторых просмотрщиках графики пустые).
3. **Скрипт-мост** `/assets/bridge.js`, подключаемый во все страницы: отслеживание секций и `postMessage` в оболочку. На старых страницах секции имеют `id="s1"…` — мост работает и там.

## 10. Черновик CLAUDE.md для репозитория

```markdown
# ML Course App

Русскоязычный курс прикладного ML (HTML-темы) + веб-приложение для чтения, тестов и интервального повторения с прогрессом в Firebase.

## Правила контента
- Перед любой правкой тем прочитать COURSE_STANDARD.md и следовать ему без исключений
  (связный текст «проблема → инструмент», задачи в формате Ситуация/Найти/Рассуждение/Решение/Вывод,
  тёмная тема, формулы только KaTeX, Q&A в <details>, графики без CDN, animation=false).
- Темы нового стандарта редактируются ТОЛЬКО в content-src/*.src.html, затем сборка
  `node tools/build.js content-src/<file>.src.html`. Сгенерированные HTML вручную не править.
- Одна тема за заход; после сборки — `node tools/check-page.mjs <file>` и визуальная проверка.
- Все числа в задачах проверять расчётом (python/node), а не на глаз.
- После сборки: `node tools/check-page.js <file>` должен завершаться с кодом 0.

## Приложение
- app/ — Vite + React + TS, Firebase (Auth Google, Firestore, Hosting), PWA.
- Контент: app/public/content (страницы), app/public/assets (katex, chart.js, bridge.js),
  manifest.json и questions.json генерируются `npm run content`.
- Прогресс: users/{uid}/topics, cards, attempts; правила — только свой uid.

## Команды
- npm run content   — собрать контент, манифест, банк вопросов
- npm run dev       — локальная разработка
- npm run build && firebase deploy — публикация (делает владелец)
```

## 11. Известные проблемы и долги

- Страницы блоков 1–9 используют CDN Chart.js и светлую тему; формулы в них — текст. До перевода на локальный Chart.js графики не работают офлайн и в некоторых просмотрщиках.
- `block3_quiz.html` и блок 3 целиком — старый формат.
- Вспомогательные скрипты прошлых сессий (генератор страниц тестов, выравнивание позиций правильных ответов, извлечение Q&A) жили во временной папке и **не сохранились** — их логику нужно восстановить в `scripts/`. Проверка страниц сохранена: `_tools/check-page.js`.
- Страницы блока 0 весят 1.2–1.5 МБ из-за встроенных шрифтов и Chart.js — решается режимом сборки для приложения.
- В Cowork был сохранён навык `ml-course-standard` (дублирует COURSE_STANDARD.md). В Claude Code роль навыка выполняет CLAUDE.md + COURSE_STANDARD.md.
