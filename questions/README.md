# Банк вопросов

Источник истины для вкладки «Тренировка». Один файл на тему: `questions/<topicId>.json` (`1.3.json`). Теория (HTML тем) и тренировка живут отдельно: правки вопросов — только здесь.

```json
{
 "topic": "1.3",
 "title": "Uplift-моделирование",
 "questions": [
  { "id": "qab12cd3", "type": "mcq", "q": "…", "options": ["…", "…", "…", "…"], "correct": 2, "explanation": "…" },
  { "id": "qef45gh6", "type": "card", "q": "…", "a": "…", "tags": ["задача у доски"] }
 ]
}
```

- `id` — постоянный (`q` + 7 символов `[a-z0-9]`). На него ссылается память интервального повторения: **не менять, не переиспользовать, не удалять вопрос без причины**. Новый вопрос можно добавить без `id` и выполнить `npm run questions -- --fix-ids`.
- `type`: `mcq` — вопрос с вариантами (`options` 2–6, `correct` — индекс верного, `explanation` — почему верно и почему остальные нет); `card` — открытый вопрос с ответом `a` (самопроверка).
- Тексты — HTML (`<b>`, `<code>`, `<p>`, `<ul>`) + формулы в `$…$` / `$$…$$` (сырой TeX, рендер KaTeX при сборке; макросы `\E`, `\Var`, `\Cov`, `\P`). Знак доллара как валюта — `&#36;`.
- Порядок вариантов приложение перемешивает. Если варианты ссылаются друг на друга («Верны A и C») — поставить `"fixedOrder": true` (лучше так не писать).
- Необязательные поля: `tags`, `level` (`junior` | `middle` | `senior`), `src` (откуда взят).

## Каким должен быть вопрос

1. **Общий, а не про кейс.** Проверяет понимание механизма, а не память о конкретной компании или эксперименте из теории. Плохо: «Сколько рядов в соревновании M5?», «Что сделал Amazon для снижения цен?». Хорошо: «Почему прогноз спроса сети решают как иерархический?».
2. **Числа — только из условия и проверены расчётом** (python/node), не на глаз. Расчётная задача допустима, если всё нужное дано в условии.
3. **Дистракторы правдоподобны** — типичные ошибки и заблуждения, а не очевидная чушь. У каждого неверного варианта свой «механизм» той же формы, что у верного («X, потому что Y»).
4. **Верный вариант не выделяется формой** — иначе тест решается без знаний («выбери самый длинный / с формулой»). Проверка в `npm run questions` (код 2):
   - верный не длиннее самого длинного неверного больше чем на 10%; лучше, чтобы самым длинным часто был неверный;
   - формула `$…$` — либо в нескольких вариантах, либо ни в одном; то же для пояснений через `;` `(` `—` `:`;
   - подробности — в `explanation`, а не в тексте верного варианта.
   Аудит всего банка: `node scripts/audit-options.js [--list]`.
5. **Объяснение** говорит, почему верный вариант верен и в чём ловушка самого соблазнительного неверного.
6. Один вопрос — одна мысль. Без «все перечисленные» и двойных отрицаний.
7. **Варианты не совпадают по смыслу.** Нет двух дистракторов с одним числом в разной записи («0.43» и «3/7 ≈ 0.43»). В вопросе «чему примерно равно» неверные варианты отстоят от верного так, чтобы «примерно» не подходило к ним (не 0.046 против 0.05).
8. **Каждое число в `explanation` — проверено расчётом**, включая объяснения дистракторов («1.65 — стандартное отклонение» должно им и быть).
9. **TeX-команды — с обратной косой чертой**: `$\log K$`, а не `$log K$` (иначе KaTeX рисует курсивные буквы «logK»). Проверка — поиск `log`, `ln`, `sqrt`, `frac`, `sigma` без `\` внутри `$…$`.
10. **Нет дублей.** Перед добавлением карточки проверить, нет ли в теме карточки на тот же вопрос (в том числе из Q&A и задач у доски одной темы). Пара «карточка + тест» на одну мысль допустима, две карточки — нет.
11. **Все данные — в условии.** Если ответ зависит от таблицы или выборки, она приводится в вопросе; «матрица признаков пяти клиентов» без самих чисел — нельзя.
12. Текст вопроса из заголовка задачи + условия собирается без склеек вида «?.»/«..».
13. **В каждой теме — вопросы «что выведет код»: минимум 2–3** (владелец, 2026-10-07). Формат — `mcq`: «Что выведет код?» + `<pre><code>` на 3–6 строк (numpy / pandas / sklearn / библиотека темы), варианты — возможные выводы в `<code>`.
    - **Сколько — по реальным тонкостям темы, а не по норме.** Где с кодом действительно нужно разбираться (бустинг, Optuna, валидация, пропуски, feature engineering), вопросов больше. В математических темах — сколько есть настоящих особенностей (для 0.1 ориентир 4–8: `ddof`, `var`/`std`, NaN, int/float). Не выдумывать вопросы ради числа и не урезать там, где тонкости есть.
    - Проверяют поведение библиотеки и типичные ловушки (значения по умолчанию, broadcasting, копия/view, выравнивание по индексу, NaN, утечки при fit/transform), а не синтаксис и не память о сигнатурах.
    - **Каждый вывод получен запуском кода** (venv в scratchpad; версии библиотек — как в приложении: numpy 2.x, pandas 3.0, sklearn 1.x), включая выводы дистракторов, если они «чей-то» реальный вывод. Формат печати — ровно как в консоли (`np.float64(…)`, `dtype`, выравнивание).
    - Дистракторы — выводы при типичной ошибке понимания (не та ось, `ddof=0` вместо 1, поведение старого pandas), а не случайные числа.

14. **Карточка (`card`) — один вопрос, одна мысль** (владелец, 2026-10-08, разбор карточек блока 0; для Q&A в тексте темы то же — `COURSE_STANDARD.md` §7.12 с примерами «как не надо / как надо»):
    - первая фраза ответа — прямой ответ; дальше 1–2 предложения «почему». Ориентир — до ~200 символов, не больше ~270;
    - не спрашивать несколько вещей сразу («Формула, среднее и дисперсия», «Пример и последствия») — разбить на карточки или сократить до одного вопроса;
    - без «хвоста» из лишних фактов после сути, без списков длиннее 3 пунктов, без чисел для заучивания (квантили, степени) — числа примера в `note`;
    - **выводы и доказательства формул — только `deep: true`**; в обычной карточке — результат и смысл, и только если он широко известен (градиент log-loss $(p - y)x$, шаг Ньютона);
    - обозначения расшифровывать в самой карточке (справки темы рядом нет); без ссылок на номера формул и темы «(4.1)» и без имён методов, которые не объяснены;
    - задачи у доски остаются как есть (материал темы), тяжёлые — `deep`.

15. **У каждого вопроса — `sec`: секция темы, где разобрано то, что он проверяет** (session 042). Туда ведёт «Почитать в теме»; без `sec` ссылка открывает начало темы. Если такой секции нет — значит, в теории это не разобрано: сначала дописать теорию (или перенести вопрос в тему, где это разобрано), потом добавлять вопрос. `npm run content` падает, если секции нет в теме.

Ориентир полноты: **не меньше 25 вопросов с вариантами на тему** плюс карточки; среди вопросов с вариантами — **не меньше 2–3 «что выведет код»** (правило 13; больше — там, где в теме есть реальные тонкости кода).

## Команды

- `npm run questions` — проверка банка: схема, уникальность id, индексы, рендер всех формул, непарные `$` (код 2 при проблемах).
- `npm run questions -- --fix-ids` — выдать id новым вопросам.
- `npm run content` — собрать `app/public/data/questions.json` (падает, если банк невалиден).
- `scripts/migrate-questions.js` — одноразовый перенос из HTML (session 004); повторно не запускать — выдаст новые id и сотрёт память повторения.
